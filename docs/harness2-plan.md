# Harness² 준비 계획 (코드·API 키 없이, 2026-10-27)

Harness²(Google Research, https://github.com/google/harness2 계열, Apache-2.0, 확인 SHA 1cfe254)는 에이전트를 둘러싼 **하네스**(시스템 프롬프트, 도구, 메모리,
스킬, 오케스트레이션 등 편집 가능한 구성요소)를 과제 실행 결과로 자동 개선하는 틀이다. 과제 단위로 제안·시험·합성(Propose–Probe–Compose)을
반복하고, 모델 가중치는 바꾸지 않는다. 실행기는 OpenCode·Codex, 벤치마크는 JobBench·LAB·WorkBuddy-Bench 를 지원한다(README).
사용자가 Runefold 에서 쓰라고 했다(2026-10-27). **지금은 계획·문서 단계라 설치·실행·비용 단계는 시작하지 않는다.**

## 1. 우리 프로젝트에서 "하네스"가 무엇인가
- 저장소 루트의 에이전트 규칙(AGENTS.md), 스킬, CI 시험(`gut`)과 감시 시험(엔진 난수 금지), 브랜치 보호.
- 개선하고 싶은 것: 에이전트가 규칙 코어를 구현할 때 **스펙 위반·결정론 위반·시험 누락**을 얼마나 적게 내는가.

## 2. 준비물 (모두 문서 작업, 비용 없음)
1. **AGENTS.md 초안**: 프로젝트 사실, 정본 위치, 하지 말 것(비밀, 엔진 난수, 공개 저장소 주의), 작업 순서(Jira → 브랜치 → 시험 → PR), 명령. (작성 후 사용자 승인)
2. **과제 목록 설계**: M1 규칙 구현을 작은 과제로 쪼갠다(예: 명중 확률 계산, 격자 이동 범위, 엄폐 판정). 각 과제에 입력 명세와 기대 동작을 적는다.
3. **채점기 설계**: 채점 = GUT 시험 통과 + 감시 시험 통과 + 명세 대조. 정답 시험은 에이전트에게 숨긴다(훈련/시험 분리).
4. **채택 기준(시험 전 고정)**: 개선 폭, 회귀 0, 반복 일관성, 비용 상한, 누설 없음. 숫자는 사용자와 함께 정한다.
5. 도집사 쪽 Spike(DJP-161, Confluence 40 검증·실험 9502730)의 P1 결과를 참고한다. 중복 작업은 하지 않는다.

## 3. 비용·안전 게이트 (사용자 결정 필요, 도집사 메모의 방침과 같음)
- 모델 접근: Claude 구독만으로는 Harness² 전체 루프가 안 된다(개선자는 Vertex 를 강제하고 실행기는 OpenCode·Codex). Anthropic API 키는 구독과 별개 결제이며 월 지출 한도를 먼저 건다.
- **API 키는 대화·파일·명령에 넣지 않는다.** 필요한 시점(과제·채점기·채택 기준이 준비된 뒤)에 이 세션이 사용자께 알리고, 사용자가 격리 환경의 셸에서 직접 환경변수로 설정한다. 회사 PC(Home1)는 쓰지 않는다.
- 비용이 드는 단계(설치, 데모, 실행)는 사용자가 상한을 정하기 전에 시작하지 않는다.
- 모델은 Fable 을 쓰지 않는다(2026-10-26 지시).

## 4. 지금 상태
- 위 2절 1~4 는 아직 작성 전(Jira RUNE-80). 실행 단계는 **NOT RUN**.
- M1 코드가 있어야 과제·채점기를 현실적으로 만들 수 있으므로 코드 단계가 시작된 뒤에 실행 계획을 확정한다.
