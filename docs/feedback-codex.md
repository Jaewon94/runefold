# 피드백 파이프라인 및 레시피 도감 UI 설계

## 1부: 피드백→Jira 파이프라인 (RUNE-64)

### 수집 창구

| 창구 | 용도 |
|------|------|
| Steam 토론 | 얼리 액세스 이후 공개 피드백 |
| Discord | 실시간 커뮤니티 피드백 |
| 구글 폼 | 플레이테스트 구조화 피드백 |

### 분류 기준

- **크래시** — 게임이 강제 종료되는 오류
- **진행불가** — 진행이 막혀 게임을 계속할 수 없는 상태
- **밸런스** — 수치·난이도 관련 의견
- **UX** — 조작·화면·흐름 관련 의견
- **기타 요청** — 기능 추가·개선 제안

### 처리 규칙

- **크래시·진행불가:** 접수 즉시 Jira 이슈 생성.
- **나머지:** 주 1회 배치 검토 후 Jira 이슈 생성 여부 결정.
- 우선순위 판단은 RUNE-51의 패치 우선순위 기준을 동일하게 적용한다.

### Discord 채널 구성 (최소)

| 채널 | 목적 |
|------|------|
| #버그리포트 | 재현 가능한 버그 접수 |
| #피드백 | 일반 의견·제안 |
| #공지 | 업데이트·일정 안내 |

운영 시간은 미정이다.

## 2부: 레시피 도감 UI 설계 (RUNE-68)

### 도감 내용

발견한 조합식을 기록하고 열람하는 화면이다.

- 표시 형식: `재료 A + 재료 B → 결과`
- 미발견 레시피는 `???`로 표시한다.

### 초기 공개 레시피

recipe-design.md 기준 검증 세트 기본 6개 레시피는 처음부터 공개한다.

### 발견 기록 흐름

1. 조합식 성공 시 도감 갱신.
2. "새 레시피 발견!" 팝업 표시.

### 화면 위치

야영지 화면 내 탭 또는 별도 도감 버튼으로 배치한다. M4에서 구현한다.

### 저장 방식

`meta.json`에 발견한 레시피 ID 목록으로 저장한다.

```json
{
  "discovered_recipes": ["r001", "r002", "r005"]
}
```

### 미결 사항

| 항목 | 선택지 |
|------|--------|
| 도감 레이아웃 | 격자형 vs 목록형 |
| 미발견 표시 방식 | `???` 단일 표시 vs 재료 힌트 부분 공개 |
