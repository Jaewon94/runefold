# Runefold 로드맵: 문서에서 출시까지 (초안 v0, 2026-10-20)

게임 개발 경험이 없는 1인이 AI 코딩 보조와 함께 Steam 출시까지 가는 큰 그림이다. 이 문서는 계획 초안이다(사용자가 2026-10-20 방향을
승인해 Confluence 04 에 올렸다. 정본은 Confluence 이고 이 파일은 사본). 근거는 세 갈래 조사(Steam 출시 절차, Godot 모범 사례, 1인 개발 프로세스)와 앞서
정리한 참고작 조사다. **일정 숫자는 출처 있는 통계가 아니라 사례에서 읽은 내 추정**이며, 그렇게 표시했다.
확인하지 못한 것은 "미확인"으로 남겼다.

## 0. 용어 (처음 보는 말)

| 말 | 뜻 |
|---|---|
| 마일스톤(M0~M6) | 큰 작업 덩어리. 각각 "끝났다"고 말할 기준이 있다 |
| 재미 확인 관문(게임 게이트) | 다음 단계로 가기 전에 "정말 재밌는가"를 사람이 확인하는 지점. 통과 못 하면 규칙을 바꾸거나 뺀다 |
| 프로토타입 | 재미를 확인하려고 거칠게 만든 시험판. 버려도 되는 것 |
| 수직 슬라이스(버티컬 슬라이스) | 게임 한 판을 처음부터 끝까지, 품질은 낮아도 전부 이어서 돌려 본 것 |
| 알파 / 베타 | 알파=기능이 다 들어갔지만 거칠다. 베타=내용이 다 들어갔고 균형을 맞추는 중 |
| 데모 | 무료 체험판. 본 게임과 별도 앱으로 Steam 에 올린다 |
| Next Fest | Valve 가 연 3회(2·6·10월) 여는 데모 행사. 위시리스트를 모으는 가장 확실한 방법으로 꼽힌다 |
| 위시리스트 | Steam 이용자가 "나중에 살 게임"으로 찜하는 것. 출시 알림이 간다 |
| Coming Soon 페이지 | 출시 전에 먼저 여는 상점 페이지 |
| 빌드 | 실제 실행 파일 묶음. Steam 은 빌드도 심사한다 |
| SteamPipe | 빌드를 Steam 에 올리는 도구와 절차 |
| GodotSteam | Godot 에서 Steam 기능(업적·클라우드 저장·입력)을 쓰게 해 주는 플러그인 |
| 헤드리스 시험 | 화면 없이 규칙만 자동으로 검사하는 시험 |

## 1. 한 장 요약

```
지금        M0 뼈대        M1~M2 전투        M3~M4 한 판+합성      M5 슬라이스     M5.5 데모     M6 Steam      출시
 문서·환경 → 도구·시험·exe → 격자·카드 ──G1,G2──→ 지도·상점·합성 ──G3──→ 직업4·유물30·보스 → 베타·Next Fest → 연동·심사 → 출시 후 2주
 행정 시작                                                                     ↑ 데모가 위시리스트를 만든다
```

- 출시 전에 **재미 확인 관문 3개(G1, G2, G3)** 를 둔다. 가장 위험한 가정(3→1 합성이 재미를 더하는가)은 G3 에서 확인한다.
- 보정 전 합계 약 **53~72주**(주 20시간 가정, 아래 표). 경험 부족 보정(×1.5)을 하면 **약 80~108주(18~26개월)**.
- 현실적 출시 목표 창: **2028년 5월~11월 안팎**(추정). 이름·범위·시간에 따라 움직인다.
- 그림·소리: **무료 에셋으로 먼저 만들고, 괜찮으면 출시 전에 제대로 교체**한다(사용자 결정 2026-10-20). 교체 가능한 구조가 전제다(3절 끝 「에셋 전략」).

## 2. 지금 확정된 것과 가정

확정(결정 장부 참조): Steam 네이티브 PC 게임, Godot 4, 합성은 같은 것 3개→1개(단계 1~3), 도트 2D 움직임 최소,
정본은 Jira·Confluence, GitHub 비공개 저장소.

계획에 쓴 가정(틀리면 일정이 바뀐다):
1. 개발은 AI 에이전트가 거의 상시 돌아간다(사용자 답 "거의 24시간", 2026-10-20 해석 — 틀리면 정정). 따라서 병목은 코딩 시간이
   아니라 **사용자의 결정·플레이테스트·검증·계정/서류/결제**와 **AI 사용 한도·비용**이다. 3절의 기간은 "주 20시간" 가정으로
   잡은 것이라 코딩 위주 단계(M0~M2, M4의 규칙 구현)는 줄어들 수 있지만, 관문·플레이테스트·콘텐츠 제작·균형 조정은 줄지 않는다.
   줄어드는 폭은 근거가 없으므로 M0~M1 을 실제로 해 본 뒤 다시 추정한다.
2. 사용자는 결정·플레이테스트·계정/서류/결제를 맡는다. 사용자의 주당 개입 시간은 미정(9절).
3. 그림·소리는 무료 에셋으로 시작하고 나중에 교체한다.

## 3. 단계별 계획

기간은 모두 내 추정이다(출처 없음). 비슷한 사례의 개발 기간과 "첫 개발 일정은 늘어난다"는 경험칙에서 잡았다.

### 단계 A. 문서와 환경 마무리 (지금~약 2주)
- 할 일: Home1 개발 환경 정리(진행 중), 1페이지 설계서, 결정 장부 갱신, 참고작 조사 정리, Jira 하위 작업 생성.
- 끝났다는 기준: 새 클론으로 어디서든 시험이 도는 환경, 설계서 1쪽에 "기둥 3~4개와 하지 않을 것"이 적혀 있다.
- **합성 빈도 계산(스프레드시트/간단한 몬테카를로)**: 풀 크기와 노드당 제시 수에 따라 한 판에 ★2·★3 가 몇 번 나오는지.
  가장 싸게 가장 위험한 가정을 시험하는 방법이다. 결과가 나쁘면 합성 규칙을 M4 이전에 고친다.
- 사용자가 할 일: 9절의 질문 답, 합성 시뮬레이션 진행 승인.

### 단계 B. M0 뼈대 (RUNE-1, 약 3~4주)
- 할 일: Godot 4.7.2 포터블 설치, 폴더 구조, 규칙 코어와 화면 분리, 시험 도구(GUT) 연결, 시드 고정 난수, Windows exe 내보내기,
  exe 를 모니터 PC 에서 실행하는 경로 확인.
- 끝났다는 기준: 시험이 `godot --headless` 로 통과(종료 코드 0), exe 가 모니터 PC 에서 뜬다.
- 사용자가 할 일: exe 실행 확인.

### 단계 C. M1 격자·이동·적 1종 (RUNE-2, 약 4~6주)
- 끝났다는 기준: 한 방에서 이동·공격·피격이 규칙대로 돌고 핵심 규칙에 자동 시험이 있다.
- **G1 재미 관문:** 이 단계만으로 10분 내내 흥미로운 결정이 있는가(사용자가 직접 플레이).

### 단계 D. M2 카드·에너지·적 AI (RUNE-3, 약 6~8주)
- 끝났다는 기준: 카드 20~30장으로 전투 한 판이 승패까지 간다. 적이 다음 행동을 예고한다. 자동 대전으로 승률을 뽑을 수 있다.
- **G2 재미 관문:** 지인 3명이 설명 없이 한 전투를 끝내고 "한 번 더"를 말하는가.
- 이 지점에서 핵심 규칙(에너지·카드·격자)을 고정한다.

### 단계 E. M3 지도·상점·유물 (RUNE-4, 약 8~10주)
- 끝났다는 기준: 1막 한 판 완주(유물 8~10종). **한 판 길이 실측** → 막 수·노드 수 결정.

### 단계 F. M4 합성 (RUNE-5, 약 6~8주)
- 끝났다는 기준: 합성 규칙·화면(야영)·시뮬레이션 모두 반영. 합성 있는/없는 버전을 비교한 결과가 기록됨.
  합성이 덱을 줄이는 문제(3→1 로 카드가 줄어듦)를 자동 대전으로 점검.
- **G3 재미 관문(가장 중요):** 합성이 결정을 더 재밌게 하는가. 아니면 규칙을 바꾸거나 뺀다.
  뺀다면 이 프로젝트의 차별점이 사라지므로 설계를 다시 보는 지점이다.
- 이 지점에서 합성 규칙을 고정한다.

### 단계 G. M5 수직 슬라이스 / 알파 (RUNE-6, 약 12~16주)
- 직업 4, 유물 30, 보스 1, 저장. 이 시점부터 **기능 추가 금지**(콘텐츠 수 고정).
- 끝났다는 기준: 처음부터 끝까지 완주 가능, 지인 5명 이상 플레이테스트, 한 판 30~45분 측정.

### 단계 H. M5.5 데모와 Next Fest (제안, 신규 이슈 필요, 약 8~12주)
- 할 일: 데모 빌드, Steam 상점 페이지(Coming Soon) 공개, Discord, Next Fest 참가, 밸런스 조정(자동 대전+플레이 기록).
- 규칙: Next Fest 는 작품당 1회. 데모 심사는 행사 3주 전까지 제출. 2027-02 회차는 이미 일정에 맞지 않으므로,
  후보는 2028년 2월 또는 6월 회차(**날짜 미확인**, 2027-02 와 2027-06 만 확인됨).
- 기준(참고, 2차 자료): 위시리스트 5천~8천을 "최소 합격선"으로 보는 글이 있다. 못 미치면 출시를 한 분기 미룬다.

### 단계 I. M6 Steam 연동과 심사 (RUNE-7, 약 6~8주)
- 할 일: GodotSteam(업적·클라우드 저장·입력), Steam Deck 점검, 가격 설정(원화 포함), 콘텐츠 설문(AI 공개 포함),
  상점 페이지·빌드 심사 제출(심사 3~5영업일, 최소 7영업일 전 제출).
- 끝났다는 기준: 비공개 빌드가 Steam 에 올라가고 실행된다.

### 단계 J. 출시와 첫 2주
- 사용자가 직접 "Release App" 을 누른다(권한 필요). 출시 후 2주는 치명 버그와 균형 핫픽스만.
- 공식 문서에 "첫 2주가 결정적"이라는 문구는 없다(미확인). 다만 신규 출시는 노출 대기열 규칙과 리뷰 점수의 영향을 받는다.

### 에셋 전략 (그림·소리)

1. **임시 도형 → 무료 에셋 → 출시 전 교체**의 3단계. M0~M2 는 도형이나 최소 그림으로 충분하다.
2. 교체 가능한 구조: 카드·유닛·유물 데이터가 스프라이트/소리 **경로만 참조**하게 한다. 그림을 바꿔도 규칙 코드는 안 건드린다.
3. 무료 에셋은 **상업 이용이 가능한 라이선스(CC0 등)만** 쓴다. 비영리(NC) 조건은 피한다. 받을 때마다 출처 URL·라이선스·작가·확인일을
   대장에 적는다(라이선스를 모르는 에셋은 쓰지 않는다).
4. 타일 16px, 480×270 규격에 맞는 팩을 고른다. 규격이 안 맞는 에셋을 늘리면 나중에 교체 비용이 커진다.
5. AI 생성 그림·소리를 쓰면 Steam 콘텐츠 설문에 공개해야 한다(코드 보조는 공개 대상이 아니라는 해석, 출시 전 원문 재확인).
6. 무료 에셋이 어디에 있고 어떤 조건인지는 이번에 조사하지 않았다(미확인). M0 때 후보 몇 곳의 라이선스를 직접 읽고 대장에 올린다.
7. 출시 전 교체 범위는 G3 이후 정한다. 게임이 재밌다고 확인된 뒤에만 그림·소리에 돈과 시간을 쓴다.
8. 무인(상시) 개발의 안전장치: 에이전트는 작업 브랜치에서만 일하고, 시험이 통과해야 병합하며, 외부에 보이는 작업(Jira·Confluence·
   GitHub 설정·결제)은 사람 승인 뒤에 한다.

## 4. 기술 기준 (M0 에서 정할 것과 권장값)

| 결정 | 권장 | 근거/비고 |
|---|---|---|
| Godot 버전 | **4.7.2 stable** 고정. 4.8 은 베타라 쓰지 않음 | godotengine.org 아카이브(확인일 2026-10-20) |
| 시험 도구 | **GUT 9.x(4.7 은 godot_4_7 브랜치)**. GdUnit4 는 4.7.1 까지만 명시 | 종료 코드 통과 0 / 실패 1 |
| 규칙 코어 | `RefCounted`/`Resource` 기반 순수 GDScript, Node 비의존. 명령을 넣으면 상태 변화·이벤트 목록이 나온다 | 공식 모범 사례 문서 |
| 난수 | 시드 고정. **직접 만든 작은 PRNG** 검토(Godot 문서가 내부 알고리즘 변경 가능성을 명시) | 저장·재현 안정 |
| 데이터 | 카드·유닛·유물을 `Resource`(.tres) 데이터로. 정적 데이터와 런타임 상태 분리. 안정적 ID | 나중에 바꾸기 어려움 |
| 저장 | JSON + `schema_version` + 마이그레이션. 외부 .tres 를 세이브로 쓰지 않음 | 보안·호환 |
| 해상도 | 480×270, stretch viewport, integer scale. **1280×800(Deck)·1280×720 에서는 정수 배율이 아니라 레터박스** 필요 | 공식 해상도 문서 |
| 코드 규칙 | 정적 타입 강제, snake_case 파일명(대소문자 사고 방지), AI 지시문에 "Godot 4.7, GDScript 2, `@export`/`await`/`create_tween`" 고정 | Godot 3 문법 혼입 방지 |
| 내보내기 | WSL 에서 `godot --headless --export-release "Windows Desktop"`. **4.5 이후 rcedit·Wine 불필요**(이전 계획에서 Wine 을 걱정했으나 해당 없음) | PR #75950, 실제 아이콘 반영은 M0 에서 시험 |
| 지역화 | 영어 우선 + 한국어 포함. PO 또는 CSV 중 선택, 한국어 폰트 폴백 | 한국어 사용자 비중이 작아도 포함 권장 |
| Steam 연동 | GodotSteam 4.23.2(GDExtension), SDK 1.65. **번들 방식과 GDExtension 을 섞지 않음** | Godot 4.7.2 와의 정확한 호환은 M0 에서 시험 |
| 도트 도구 | Pixelorama(MIT, 무료) 또는 Aseprite(최소 $19.99). LibreSprite 는 라이선스 표기가 문서마다 다름 | 도입 시 URL·확인일 기록 |
| 버전 관리 | LFS 는 에셋이 커질 때. `export_credentials.cfg` 는 커밋 금지 | |

**나중에 바꾸기 어려운 것(처음부터 잘 정할 것):** 규칙/화면 분리, 난수 방식과 호출 순서, 저장 형식, ID 체계, 파일명 규칙,
해상도(모든 도트 크기가 종속), 지역화 키, GodotSteam 설치 방식.
