# Runefold 아트 방향 — 네오 다크세이버 스타일 (초안 v0.1)

이 문서는 룬폴드의 시각 언어를 정의한다. 게임 설계의 정본은 [design.md](design.md) 이며 해상도·타일 수치는 [resolution-mockup.md](resolution-mockup.md) 를 따른다. 어긋나면 Confluence 가 맞다.

상태 표기: **확정** = 사용자가 정했다 / **잠정** = 실측·검토 뒤 확정 / **미정** = 아직 정하지 않았다

## 1. 핵심 분위기 — 네오 다크세이버란 무엇인가

**네오 다크세이버**는 라피스(Lapis)·네오 다크세이버 계열 전술 JRPG 에서 온 분위기 레퍼런스다. 그러나 룬폴드는 그 코드나 에셋을 쓰지 않고, 아래 키워드가 가리키는 분위기를 우리 도트로 새로 빚는다.

### 키워드 (5~7개)

| # | 키워드 | 뜻 |
|---|---|---|
| 1 | **어둠 속 긴장** | 배경은 짙고 어두우며, 전투 공간은 항상 위협감이 있다 |
| 2 | **묵직한 판타지** | 빛나는 화려함보다 두꺼운 테두리와 무게감 있는 색면 |
| 3 | **현대적 도트** | 레트로 향수가 목적이 아니라 제작 효율과 명확한 실루엣이 목적 |
| 4 | **카드의 긴장감** | 카드 UI 가 전술적 선택지를 시각화해야 한다. 화려한 이펙트보다 정보 명료성 우선 |
| 5 | **침묵하는 영웅** | 캐릭터는 과도하게 표현하지 않는다. 대기 프레임은 절제, 행동 피드백은 임팩트 |
| 6 | **타락의 색** | 적과 보스는 부패·타락을 상징하는 색(보라·탁한 붉음)으로 구분 |
| 7 | **선택의 무게** | 합성·승급 후 외형 변화가 분명해, 플레이어가 키운 것을 잃었을 때 상실감이 느껴진다 |

## 2. 팔레트 지침

### 주 색조 범위

| 역할 | 색조 범위 | 명도 | 채도 | 용도 |
|---|---|---|---|---|
| 배경 (타일·바닥) | 청회색·남색·흑갈색 | 낮음 (10~30%) | 낮음 (5~20%) | 전장 타일, 어두운 지하·황야 |
| 중간 톤 (벽·오브젝트) | 회청·갈회·무채회 | 중간 (30~55%) | 낮음~중간 (10~30%) | 벽, 장애물, 엄폐물 |
| 캐릭터 기본 | 세계별 주색 + 흑/회 혼합 | 중간~높음 (40~70%) | 중간 (25~50%) | 아군 스프라이트 |
| UI 패널 | 흑갈색·짙은 남색 | 낮음 (15~35%) | 낮음 (5~15%) | 카드 배경, 손패 영역, 패널 |

### 강조색 사용 원칙

- 강조색은 **한 화면에 최대 2가지**만 동시에 활성화한다.
- 강조색은 행동 가능한 상태·선택 가능한 요소에만 쓴다. 장식용 빛 효과에는 쓰지 않는다.
- 등급별 강조색은 design.md 의 등급 표를 따른다.

| 강조색 | 용도 |
|---|---|
| 흰색 번쩍임 (순간) | 피격 피드백. 1~2프레임만 사용 |
| 금색·황색 | 전설 등급 테두리, 승급 확정 효과 |
| 청록·밝은 파랑 | 행동 범위 표시, 선택된 타일 하이라이트 |
| 붉은 주황 | 위험 경고 (보스 어그로, 치명적 범위 예고) |
| 보라·탁한 자주 | 적 스프라이트, 타락 상태, 저주 유물 테두리 |

### 금지 색상

- **순도 100% 원색** (H=0/120/240, S=100%, V=100%): 눈에 피로하고 도트의 색면 무게감을 무너뜨린다.
- **흰색 배경·밝은 파스텔 전면**: 어두운 분위기 파괴.
- **무지개 그라디언트 효과**: 2D 도트 텍스처와 맞지 않는다.
- **연두·형광 노랑**: 세계관과 어울리지 않는 과도한 경쾌함.

## 3. 캐릭터 도트 규격

### 기준 수치 (잠정, design.md 와 동일)

| 항목 | 수치 | 상태 |
|---|---|---|
| 기준 해상도 | 640×360 | 잠정 |
| 타일 크기 | 32×32 px | 잠정 |
| 캐릭터 스프라이트 | 16×24 px 또는 24×32 px 권장 | 잠정 |
| 몬스터 스프라이트 | 16×16~32×32 px (크기에 따라 위협감 조절) | 잠정 |

- **캐릭터 스프라이트 권장 크기 근거**: 타일 32px 기준에서 16×24 는 한 타일보다 약간 작아 격자 안에 자연스럽게 들어간다. 보스·대형 몬스터는 2×2 타일(64×64)까지 허용.

### 애니메이션 원칙 (확정, design.md 6절)

| 상태 | 처리 방식 | 프레임 수 |
|---|---|---|
| 대기 (Idle) | 스프라이트 루프 | 2~4프레임 |
| 이동 | 대기 프레임 그대로 타일 간 트윈 슬라이딩 | 별도 프레임 없음 |
| 공격 | 앞으로 살짝 내딛었다 복귀하는 트윈 | 별도 프레임 없음 |
| 피격 | 흰색 번쩍임 1~2프레임 + 뒤로 밀림 트윈 | 1~2프레임 (흰색 오버레이) |
| 사망 | 페이드아웃 또는 넘어짐 정지컷 | 1프레임 (정지 컷) |
| 카드·유물 아이콘 | 정지 아이콘 (32×32 px 권장) | 1프레임 |

- 걷기·달리기 루프 프레임은 **만들지 않는다.**
- 일러스트 풀 컷(카드 이미지 전면 일러스트)은 **쓰지 않는다.** 아이콘 형태로 처리.

## 4. UI/UX 시각 방향

### 4-1. 카드 UI

| 요소 | 지침 |
|---|---|
| 카드 크기 | 손패 영역 내에서 겹침 표시 가능한 크기 (대략 24×36 px 기준 아이콘 + 수치) |
| 카드 배경 | 짙은 흑갈색·남색 패널. 등급에 따라 테두리 색 변경 (design.md 등급 표 참조) |
| 카드 아이콘 | 32×32 px 정지 이미지. 직업·효과를 상징하는 실루엣 중심 |
| 비용 표시 | 카드 왼쪽 상단에 에너지 수치. 가독성 최우선, 폰트는 픽셀 전용 |
| 사용 불가 상태 | 전체 어둡게 (알파 50% 어둡힘). 비용 부족 시 비용 수치 붉게 표시 |
| 직업 태그 | 카드 하단에 소형 태그 아이콘. 사용 가능 직업이 없을 때 회색 처리 |

### 4-2. 손패 레이아웃

- 손패 5장은 화면 하단 중앙에 부채꼴 또는 일렬 배치. 선택 시 위로 들어올림.
- 에너지 3개 표시는 손패 위 혹은 좌측 패널에 아이콘 형태로.
- 640×360 해상도에서 손패 영역은 하단 80~100 px 를 차지한다(전장 영역 보호 우선).

### 4-3. 격자 타일 시각화

| 상태 | 색 처리 |
|---|---|
| 기본 타일 | 어두운 바닥 텍스처, 선은 최소화(배경에 녹아들게) |
| 이동 가능 범위 | 청록 반투명 오버레이 |
| 공격 범위 | 붉은 반투명 오버레이 |
| 선택된 유닛 타일 | 흰색 테두리 + 하단 발판 하이라이트 |
| 장애물·엄폐 | 타일보다 채도 높은 오브젝트, 엄폐 아이콘 중첩 |
| 적 예고 범위 | 주황 반투명 오버레이 (틱 카운터 채택 시 카운터 숫자 표시) |

- **타일 선(그리드 라인)**은 기본 숨기거나 어둡게 유지한다. 선택 및 범위 표시 시에만 드러난다.

## 5. 직업별 시각 구분 — 7티어 외형 변화 원칙

승급(★1→★7)마다 외형이 달라져야 한다. 100개 이상 직업을 솔로 개발자가 감당하려면 **모듈화**가 핵심이다.

### 외형 변화 원칙

| 티어 | 외형 변화 방향 |
|---|---|
| ★1 (기본) | 단순한 실루엣, 소박한 복장. 색조는 세계별 기본 팔레트 |
| ★2~★3 | 부위(무기·어깨·두건 등) 1~2가지 추가 또는 색 채도 상승. 기본 스프라이트 재활용 + 오버레이 레이어 |
| ★4~★5 | 실루엣이 뚜렷하게 변한다 (망토·갑주·장식). 기존 부품 교체 + 신규 부품 1~2가지 |
| ★6~★7 | 색조가 어두워지고 광원 효과(발광 테두리, 빛나는 문양)가 추가된다. 고유한 실루엣. 솔로 개발 단계에서는 미정 |

### 모듈화 전략

- 스프라이트를 **몸통 / 무기 / 머리 / 장식** 레이어로 분리해 조합한다.
- 같은 세계의 기본 직업은 몸통 레이어를 공유하고 장식·색조만 바꾼다.
- 크로스오버 직업은 두 세계의 레이어를 혼합해 새 실루엣을 만든다.
- ★1~★3 는 팔레트 교환 + 레이어 추가로 처리해 신규 그림 없이 구분 가능하게 한다.

### 솔로 무료 에셋 단계 현실안

- ★1~★3: 무료 에셋 공유 + 색조 변환(Hue Shift)
- ★4~★5: 무료 에셋 부품 조합 + 수동 수정
- ★6~★7: AI 보조 생성 후 도트 수정 (Steam 콘텐츠 설문에 AI 생성 공개 필수)

## 6. 참고 방향 요약 — 공개 아트 방향에서 가져오는 원칙

참고작 코드·에셋·바이너리는 가져오지 않는다. 공개된 아트 방향 발표·인터뷰·GDC 강연에서 얻은 결론만 한국어로 요약한다.

| 참고 방향 | 룬폴드 적용 결론 |
|---|---|
| **어둡고 고통스러운 세계 (Darkest Dungeon 계열)** | 배경·환경 타일은 밝지 않게. 화면에 여백보다 위협이 더 많아야 한다. 파스텔·밝은 배경은 쓰지 않는다 |
| **빠른 피드백, 최소 애니메이션 (Dead Cells 스타일)** | 도트라도 타격감은 흰 번쩍임·밀림 트윈으로 낸다. 공격 애니메이션 없이도 임팩트를 만들 수 있다 |
| **정보 밀도 높은 전술 UI (Into the Breach 계열)** | 격자·범위·피해 예고를 한 화면에 동시에 읽을 수 있어야 한다. 반투명 오버레이로 정보를 겹쳐 표현 |
| **카드 실루엣 중심 아이콘 (Slay the Spire 계열)** | 카드 아이콘은 작아도 효과를 단번에 알 수 있는 실루엣이어야 한다. 복잡한 일러스트보다 명확한 아이콘 |
| **승급이 눈으로 보이는 성장감** | 합성·승급 후 스프라이트가 달라져야 한다. 외형 변화가 없으면 성장 피드백이 약해진다 |
| **팔레트 제약으로 통일감 유지** | 세계별 주색조를 제한해 캐릭터가 각자 달라 보이면서도 같은 세계관에 있는 느낌을 준다 |

## 7. 솔로 개발자 현실 제약

### 7-1. AI 이미지 보조

- Aseprite 또는 LibreSprite 로 도트 제작이 기본이나, AI 이미지 도구(예: 픽셀아트 특화 모델)로 초안을 뽑고 수작업으로 정돈하는 흐름을 허용한다.
- **AI 생성 이미지를 사용할 경우 Steam 콘텐츠 조사(Content Survey)에 반드시 공개 표기**한다(2026 Steam 정책 기준).
- 생성 도구 이름·버전·라이선스·사용일은 [docs/third-party.md](third-party.md) 에 기록한다.

### 7-2. 최소 프레임 원칙

- 직업·몬스터 1종당 필요한 그림은 **대기 2~4프레임이 전부**다. 이동·공격·피격은 트윈·효과로 처리.
- 이 원칙 덕분에 직업 100종 = 200~400프레임. 일러스트 풀 컷 방식 대비 1/5 이하.
- 검증 세트(기본 6 + 합성 6) 단계는 임시 도형·색 블록으로 시작한다. 에셋 교체는 M5 이후.

### 7-3. 재사용 모듈화 전략

- 레이어 방식(몸통 / 무기 / 머리 / 장식): 동일 레이어를 세계 내 직업이 공유. 직업 100종에 필요한 고유 그림을 40~60종 수준으로 줄인다.
- 팔레트 교환: 같은 실루엣에 색조만 바꿔 ★1→★3 구간 외형 변화를 낸다.
- 타일셋 재사용: 세계별 타일셋(바닥·벽·오브젝트)을 모듈로 만들어 전장마다 조합한다. 초기에는 무료 32px 타일셋 팩을 활용한다(출처는 [docs/asset-sources.md](asset-sources.md) 에 기록).
- 에셋 라이선스: 받을 때 출처 URL·확인일을 기록한다. 저장소 공개이므로 라이선스 요건을 어긴 에셋은 올리지 않는다.

### 7-4. 도구 후보 (라이선스 확인 대기)

| 도구 | 유형 | 비고 |
|---|---|---|
| Aseprite | 도트 편집기 (유료, 소스 공개) | 업계 표준. 가격·라이선스는 도입 시점에 공식 사이트에서 확인 |
| LibreSprite | Aseprite 포크 (무료, 오픈소스) | 설치 전 최신 포크 상태·라이선스 확인 필요 |
| Pixelorama | 무료 픽셀 편집기 (Godot 기반) | Godot 연동 가능성 있음. 도입 시점에 확인 |

## AI 사용 규칙 (AGENTS.md 준수)
- 참고 게임(Darkest Dungeon·Dead Cells 등)의 이미지·스크린샷을 AI 프롬프트 입력으로 쓰지 않는다.
- 프롬프트는 한국어 스타일 서술만 사용한다.
- AI 생성 산출물은 `docs/third-party.md` 에 모델명·날짜·프롬프트 요약을 기록한다.
- Steam 콘텐츠 설문에 AI 생성 사용 사실을 공개한다.

- 캐릭터 포트레이트(카드 또는 소대 UI용 얼굴 이미지) 포함 여부와 크기: **미정**
- 세계별 주색조 테이블 (세계 14개 각각의 대표 색조): **미정** (roster-plan.md 와 함께 확정 예정)
- 카드 UI 의 정확한 픽셀 크기·손패 레이아웃 좌표: **미정** (해상도 목업 RUNE-42 결과 후 확정)
- 몬스터 스프라이트 크기·수량 기준: **미정** (M1 이후 실측)
- 이펙트(파티클) 시스템 방향: **미정** (M2 이후 실측)
