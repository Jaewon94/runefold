# EGM 2차 시험 결과: OpenCode 위에서 roster-plan.md 검토 (2026-10-29)

사전 등록 기준은 [egm-trial.md](egm-trial.md) 3절이고 **바꾸지 않았다.** 1차 결과는 [egm-trial-result.md](egm-trial-result.md).
이번 시험은 같은 기준을 **OpenCode v2.2.0 + 일반 서브에이전트(`goldfish`)** 조합에 적용한 것이다. 대상 `docs/roster-plan.md`(마지막 변경 커밋 `4f3538e`).
**EGM 플러그인을 직접 실행한 것이 아니다.** EGM 클론(커밋 `3d0b348`)의 페르소나 파일을 서브에이전트가 읽게 했다. 모델 Sonnet 5.5.
검토 실행은 OpenCode, 지적 확인과 판정은 이 세션(Claude Code)이 했다. 같은 모델 계열이라 독립성은 낮다.

## 판정: 기준 1·2·4 충족, 기준 3은 집계 방식에 따라 갈려 **보류**
| 기준 | 결과 |
|---|---|
| 1. 새로 발견한 유효 지적 5개 이상 | **충족.** 통합 항목 A1~A7·A9·A11·A12·A19 를 이 세션이 원본 줄과 직접 대조해 일치를 확인했다(아래 표). 이 문서에 대한 이전 독립 검토가 없어 중복·신규 구분은 하지 못했다 |
| 2. 오탐률 30% 이하 | **충족(확인한 범위).** 직접 대조한 12개 항목에서 사실이 틀린 지적은 0개. 검토자 보고서가 스스로 정정한 것은 줄 번호 1건(53행→54행)과 표현 1건뿐이다. 직접 확인하지 못한 항목은 유효로 세지 않았다 |
| 3. 서브에이전트 토큰 60만 이하 | **보류.** 사전 등록 문서가 캐시 읽기를 합산하는지 정하지 않았다. 아래 숫자 참고 |
| 4. 누설 없음 | **충족(프롬프트 기준).** 서브에이전트 6개 세션 모두 사용자 메시지가 1개이고 내용은 페르소나 경로·대상 문서 경로·모드뿐이다. 카나리·이전 검토 결과·대화 결론 없음. 다만 파일시스템과 프로젝트 지침은 격리되지 않는다. 일부가 `docs/*.md` 목록으로 `egm-trial-result.md`·`harness2-plan.md` 파일명을 보았으나 **읽지는 않았다**(도구 호출 기록) |

### 기준 3 숫자 (OpenCode 세션 기록, 서브에이전트 6개 합계)
| 집계 | 토큰 |
|---|---|
| 입력+출력+추론+캐시 쓰기 | 약 17만 (입력 58, 출력 25,963, 추론 17,441, 캐시 쓰기 126,530) |
| 위에 캐시 읽기 포함 | 약 67.6만 (캐시 읽기 506,436 추가) |
| 비용 | 서브에이전트 약 $0.80, 오케스트레이터 세션 약 $0.66 |

글자 그대로 "모든 토큰"으로 읽으면 60만을 넘어 **미충족**이고, 캐시 읽기를 빼면 충족이다. **어느 쪽이 맞는지는 사용자가 정할 일이며**, 이 세션이 결과를 본 뒤에 유리한 쪽을 고르지 않았다. 1차 시험의 27.2만이 어떤 집계였는지도 확인하지 못했다.

## 이 시험이 벗어난 점
- 9단계(구현 준비도)는 돌리지 않았다. 대상이 구현 계획이 아니라 스킬 지침의 "구현 계획 없음" 경로가 적용됐다.
- 통합·분류는 `synthesizer.md` 서브에이전트가 아니라 오케스트레이터 세션이 했다. 통합 단계는 격리된 검토가 아니다.
- `structural.md`·`style.md` 를 7단계에 추가했다(EGM 원본 스킬의 검토자 목록). 8단계 Zoom Out 은 이전 보고서를 받지 않아 5단계와 같은 입력의 두 번째 표본이다.
- 표준 문서 경로를 프롬프트에 넣지 않아 표준 준수는 판정되지 않았다.
- 처음 두 번의 실행은 비대화형 권한 거부와 `-s` + `--model` 조합의 정지로 시작하지 못했다(원인은 정황으로만 확인).

## 해석과 한계
- 1차 결과와 같은 방향이다. EGM 페르소나는 **문서끼리의 불일치와 명세 공백**을 잘 찾았고, 규칙 상호작용의 수치 분석은 하지 않았다.
- 같은 계열 모델이 검토하고 같은 계열 모델이 판정했다. 지적 개수만으로 효과를 단정하지 않는다.
- 이 결과로 EGM 정기 사용을 확정하지 않는다. 기준 3의 집계 방식을 사용자가 정한 뒤 판정한다.
