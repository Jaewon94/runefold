## 바로잡은 규칙 (design.md 기준)

합성은 **단계마다 같은 것 3개 → 1개**다.

| 합성 | 재료 | 기본 재료로 환산 |
|---|---|---|
| 1 → 2단계 | 같은 이름·같은 1단계 3개 | 3개 |
| 2 → 3단계 | 같은 이름·같은 2단계 3개 | 9개 |

- 단계를 건너뛰지 않는다. 3단계는 기본 재료 9개분이며, 3단계가 되려면 2단계를 먼저 3개 만들어야 한다.
- 따라서 "반쯤 합성된 상태"(같은 것 2개 보유)는 **각 단계마다 존재한다**. 합성 가능 표시(merge-systems.md 7절 10번 질문)가 단계마다 필요한지 검토 대상이다.
- SAP 식 경험치 지분 누적이 적용되지 않는다는 결론은 그대로다. 다만 이유는 "중간 단계가 없어서"가 아니라 "합성이 이산적인 3개→1개여서"이다. TFT 와는 같은 구조(3개 → 2성, 2성 3개 → 3성)다.

## 증가폭 비교를 단계별로 다시 적는다

merge-systems.md 1-2 의 TFT 수치(한 챔피언 기준 계산, 낮은 확신도, 일반 규칙 미확인)를 단계 단위로 읽는다.

| 단계 | 누적 배율(체력) | 이전 단계 대비 | 재료 3개 대비 효율 |
|---|---|---|---|
| TFT 1성 → 2성 | ×1.8 | ×1.8 | 1.8 / 3 = 0.6 |
| TFT 2성 → 3성 | ×3.24 | ×1.8 | 1.8 / 3 = 0.6 |

- 3.24 는 1.8 의 제곱이고, 3성은 기본 재료 9개분이다. 즉 이 한 사례에서는 **단계마다 같은 배율(×1.8)을 곱하는 구조**로 읽힌다. "3성만 효율이 떨어진다"는 5-3 의 서술(3.24/9 대 1.8/3)은 비교 기준이 어긋나 있었다. 재료 9개 대비로 보면 3.24/9 = 0.36 이고 단계별로는 둘 다 0.6 이다.
- 이 값은 한 챔피언(Set 15 브라움)의 체력 기준 계산이며 공격은 ×1.5 → ×2.25(역시 단계마다 ×1.5)다. 일반 규칙으로는 확인되지 않았고 낮은 확신도다.
- Runefold 의 ★ 단계별 증가폭을 정하는 출발점으로는 "단계마다 같은 배율을 곱하는 방식"과 "재료 3개 대비 효율 0.5~0.7 대"를 후보로 둘 수 있다. **참고일 뿐 확정 수치가 아니며**, SAP·TFT 의 단계별 실측(7절 6번 질문)을 본 뒤 정한다.
