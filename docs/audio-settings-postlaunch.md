# 오디오 뼈대 · 설정 메뉴 · 출시 후 패치 계획 (RUNE-49·50·51)

이 문서는 RUNE-49(오디오 뼈대), RUNE-50(설정 메뉴), RUNE-51(출시 후 1~3개월 패치 계획) 세 설계를 하나로 묶은 것이다. 세 이슈는 각각 M3·M5·M6 에 걸쳐 있으나 내용이 연결되어 있어 함께 관리한다.

상태 표기: **확정** = 사용자가 정했다 / **잠정** = 시험·실측 뒤 확정한다 / **미정** = 아직 정하지 않았다.

---

## 1부: 오디오 뼈대 (RUNE-49, M3)

### 오디오 버스 구조

**잠정.** 솔로 인디 2D 도트 전술 로그라이크에 맞춘 최소 버스 구성이다.

```
Master
├── BGM   (배경 음악)
├── SFX   (효과음)
└── UI    (메뉴·버튼 소리)
```

- Master 는 전체 볼륨 조절과 음소거를 담당한다.
- BGM·SFX·UI 는 각각 독립 볼륨을 가지며, dB 단위로 연산한다(`linear_to_db` / `db_to_linear`).
- 버스는 Godot 4 의 AudioServer 에 코드로 등록하고, Project Settings > Audio 에서는 기본 Master 버스만 둔다.

### BGM 5트랙

| 트랙 ID | 재생 상황 | 루프 |
|---|---|---|
| `bgm_map` | 탐색(지도·노드 선택 화면) | 예 |
| `bgm_battle` | 전투(일반) | 예 |
| `bgm_boss` | 전투(보스) | 예 |
| `bgm_camp` | 야영지·정리 화면 | 예 |
| `bgm_ending` | 엔딩·클리어 화면 | 아니오 |

- 파일 형식: `.ogg`(Godot 4 권장, 스트리밍 재생). `.wav` 는 짧은 효과음 전용.
- 각 트랙은 `AudioStreamPlayer` 노드 하나를 할당한다(씬 상단 싱글턴).

### SFX 카테고리

| 카테고리 | 예시 소리 |
|---|---|
| 카드 사용 | 카드 슬라이드·발동 효과음 |
| 이동 | 유닛 발소리(격자 이동 1회) |
| 공격 — 근거리 | 칼·도끼·주먹 충격음 |
| 공격 — 중거리 | 투사체 발사음 |
| 공격 — 원거리 | 활·총기 발사음 |
| 피격 | 데미지 수신음, 방어막 흡수음 |
| 사망 | 유닛 소멸·퇴장음 |
| 합성·승급 | 합성 연출음(반짝임·변환) |
| UI 버튼 | 클릭, 호버, 확인, 취소 |

- SFX 는 `AudioStreamPlayer2D` 또는 `AudioStreamPlayer` 로 재생한다.
- 같은 소리가 겹쳐 재생되는 것을 막으려면 `max_polyphony` 를 카테고리별로 제한한다(잠정: 공격음 4, 나머지 2).

### 음악 상태 전환

**잠정.** 상태기는 씬 싱글턴(`AudioManager.gd`)에서 관리한다.

```
지도 화면  → 전투 진입: bgm_map → bgm_battle  크로스페이드 0.5초
전투 종료  → 지도 복귀: bgm_battle → bgm_map  크로스페이드 0.5초
전투 진입  → 보스 전투: bgm_battle → bgm_boss 크로스페이드 0.5초
야영지 진입: 어느 BGM → bgm_camp             크로스페이드 0.5초
클리어    : 모든 BGM 정지 → bgm_ending 재생
```

- 크로스페이드: 현재 트랙 볼륨을 0.5초 동안 0으로 낮추면서 새 트랙 볼륨을 0.5초 동안 최대로 올린다(`Tween.tween_property`).
- 전투 중 사망·패배는 SFX 만 재생하고 BGM 을 즉시 정지한다(잠정).

### 볼륨 설정 저장

**잠정.** 설정은 `user://settings.cfg`(`ConfigFile`)에 저장한다.

```gdscript
# 저장 키 예시
[audio]
bgm_volume = 80   # 0~100 정수
sfx_volume = 80
ui_volume  = 80
mute_all   = false
```

- 볼륨 0~100 값을 선형 비율로 바꿔 dB 로 적용한다: `AudioServer.set_bus_volume_db(idx, linear_to_db(val / 100.0))`.
- 볼륨 0 이면 음소거(`AudioServer.set_bus_mute`)도 함께 켠다.
- 게임 시작 시 설정 파일을 읽어 적용하고, 없으면 기본값(80)을 쓴다.

### 미확정 항목

| 항목 | 상태 | 비고 |
|---|---|---|
| BGM 라이선스 방식 | 미정 | CC0 무료 / 외주 의뢰 / AI 생성 세 옵션 검토 중 |
| SFX 출처 | 미정 | CC0 무료 에셋 우선 탐색(RUNE-20 참조) |
| 크로스페이드 시간(0.5초) | 잠정 | M3 플레이테스트에서 체감 후 조정 |
| 버스 이퀄라이저·컴프레서 | 미정 | M5 이후 필요하면 추가 |

BGM·SFX 를 도입할 때는 출처 URL·라이선스·확인일을 `docs/third-party.md` 에 반드시 기록한다.

## 2부: 설정 메뉴 (RUNE-50, M5)

### 목표

M5 수직 슬라이스에 포함할 최소 설정 메뉴이다. 설정 메뉴도 패드로 완주 가능해야 한다(RUNE-48 입력 추상화 전제).

### 화면(Display) 설정

| 항목 | 옵션 | 상태 |
|---|---|---|
| 전체화면 토글 | 전체화면 / 창 모드 | 잠정 |
| 정수 배율 | ×2 / ×3 / ×4 / 자동 | 잠정 |
| 수직 동기화(V-Sync) | 켬 / 끔 | 잠정 |

- 정수 배율 자동: 화면 크기에서 최대 정수 배율을 계산해 적용(`get_viewport().content_scale_size`).
- 기준 해상도 640×360(잠정, `resolution-mockup.md` 참조).
- 창 크기는 변경 즉시 저장한다.

### 오디오(Audio) 설정

| 항목 | 범위 | 상태 |
|---|---|---|
| BGM 볼륨 | 0~100 슬라이더 | 잠정 |
| SFX 볼륨 | 0~100 슬라이더 | 잠정 |
| 음소거(Mute) | 토글 | 잠정 |

- 슬라이더 조작 즉시 `AudioManager.gd` 에 반영하고 설정 파일에 저장한다.
- UI 볼륨 슬라이더는 M5 에서 필요하면 추가한다(잠정: BGM·SFX 두 개만).

### 언어(Language) 설정

| 항목 | 옵션 | 상태 |
|---|---|---|
| 표시 언어 | 한국어 / English | 잠정 |

- M5a 텍스트 동결(RUNE-58) 이후 번역 문자열이 확정되면 활성화한다.
- 언어 변경 즉시 `TranslationServer.set_locale` 을 호출하고 UI 를 갱신한다.

### 조작(Controls) 설정

| 항목 | 상태 | 비고 |
|---|---|---|
| 키 리매핑 UI | 미정(M5 이후) | 핵심은 아님. RUNE-48 입력 추상화가 선행 조건 |

- M5 에서는 기본 키 배열만 표시하고 리매핑은 구현하지 않는다.

### 저장 위치와 즉시 저장 규칙

- 저장 위치: `user://settings.cfg`(`ConfigFile`). Godot 의 `user://` 는 OS 별 사용자 데이터 폴더에 맞게 해석된다.
- **즉시 저장**: 창 크기·배율·볼륨은 변경 직후 저장한다. 게임을 강제 종료해도 설정이 유지된다.
- 설정 파일 스키마:

```
[display]
fullscreen   = false
scale_mode   = "auto"   # "2", "3", "4", "auto"
vsync        = true

[audio]
bgm_volume   = 80
sfx_volume   = 80
mute_all     = false

[language]
locale       = "ko"     # "ko", "en"
```

### 패드 완주 요건

RUNE-48 입력 추상화를 전제로 설정 메뉴 전체를 패드만으로 탐색·변경·저장할 수 있어야 한다.

- 포커스 탐색: `ui_up` / `ui_down` / `ui_left` / `ui_right` 액션.
- 슬라이더: `ui_left` / `ui_right` 로 값 조정.
- 토글·버튼: `ui_accept` 로 확정.
- 설정 메뉴 열기·닫기: `ui_cancel` 액션.

## 3부: 출시 후 1~3개월 패치 계획 (RUNE-51, M6)

### 버그 제보 창구

| 창구 | 역할 |
|---|---|
| Steam 토론 | 공개 버그 제보·공지 |
| Discord | 빠른 소통·커뮤니티 |
| Jira RUNE 프로젝트 | 내부 수집·우선순위 관리 |

- Steam 토론과 Discord 의 제보는 담당자(사용자)가 Jira 이슈로 변환해 관리한다.
- 크래시·데이터 손실 제보는 로그 파일 첨부를 안내한다(로그 파일 경로는 게임 내 표시, RUNE-50 에 포함).

### 패치 우선순위

높은 순서부터:

1. **크래시** — 게임이 비정상 종료되는 모든 경우
2. **데이터 손실** — 세이브 파일 손상·소실
3. **진행 불가** — 특정 노드·전투·UI 에서 막히는 경우
4. **밸런스 이상** — 명백히 지배적이거나 의미 없는 전략
5. **QoL(편의성)** — 커뮤니티 피드백 기반 개선

### 출시 후 1개월

| 범주 | 내용 |
|---|---|
| 크래시 수정 | 제보된 크래시 전량 수정 목표 |
| 진행 불가 수정 | 특정 경로에서 게임이 막히는 버그 수정 |
| 명백한 밸런스 이상 대응 | 특정 직업·카드·유물이 다른 모든 선택지를 압도하는 경우 조정 |
| 패치 배포 | SteamPipe 를 통해 빌드 업데이트, 패치 노트 Steam 공지 |

- 이 기간에는 **새 콘텐츠 추가 금지**. 버그 수정과 긴급 밸런스만 한다.
- 패치 배포 전 CI 헤드리스 시험을 통과해야 한다(RUNE-43).

### 출시 후 2~3개월

| 범주 | 내용 |
|---|---|
| QoL 개선 | 커뮤니티 요청이 많은 편의 기능(UI 정보 추가, 조작 개선 등) |
| 밸런스 조정 | Steam 리뷰·Discord 피드백을 바탕으로 2차 밸런스 패치 |
| 번역 오류 수정 | 한국어·영어 텍스트 오탈자·어색한 번역 수정 |
| 패치 노트 | 변경 내역을 Steam 공지와 Discord 에 함께 게시 |

### 콘텐츠 DLC

**미정.** 출시 후 판매량과 커뮤니티 피드백을 보고 결정한다. 1~3개월 패치 기간에는 결정하지 않는다.

### 운영 도구

| 도구 | 용도 |
|---|---|
| Jira RUNE | 버그·작업 추적 |
| GitHub Actions CI | 패치 빌드 검증 |
| SteamPipe | 빌드 배포 |
| Steam 공지 | 패치 노트 게시 |
| Discord | 커뮤니티 소통 |
