# 조기 검증 계획 (RUNE-74 · RUNE-75)

이 문서는 두 가지 조기 검증 계획을 담는다.
1부는 합성 시스템을 M4 전에 미리 시험하는 **합성 조기 시험(RUNE-74)**,
2부는 낯선 사람에게 가능한 빨리 피드백을 받는 **외부 검증 전진(RUNE-75)**이다.

두 계획 모두 재미 확인 관문 G3(M4 끝, RUNE-25) 이전에 실패 신호를 잡아 설계 방향 전환 비용을 줄이는 것이 목적이다.

---

## 1부: 합성 조기 시험 계획 (RUNE-74)

### 목적

합성(승급·조합식)이 실제로 재미있는지 M4 완료 전에 먼저 확인한다.
G3(합성 재미 관문)의 **사전 신호**로, 합성이 기대에 못 미치면 M4 설계를 고칠 수 있다.
합성 관련 설계는 [design.md](design.md)의 「합성과 등급」 절과 [roadmap.md](roadmap.md)의 M4(RUNE-5) 항목을 따른다.

### 시험 시점

M2(카드·에너지·적 AI) 완료 직후, G2(지인 3명 관문, RUNE-22) 전.
지도·상점 없이, 전투와 카드가 동작하는 상태에서 합성만 먼저 끼워서 본다.

### 시험 방식: 스크립트된 보상 순서

- **고정 시드** + **획득 순서 고정**: 지도·상점 없이 정해진 보상 순서를 그대로 제공한다.
- 같은 유닛 3개가 반드시 손에 들어오도록 순서를 설계해 승급 발생을 보장한다.
- 조합식 재료 2~3개도 정해진 순서에 포함해 조합식 결과를 최소 1회 체험하게 한다.
- 구현 범위: 야영지·정리 화면 UI와 합성 확정 로직만 있으면 된다(지도·상점·보스 불필요).

### 검증 항목

| 번호 | 항목 | 확인 방법 |
|---|---|---|
| ① | 승급(★3) 달성 체감 | 플레이어가 ★3 달성 순간을 알아채고 반응하는가 |
| ② | 조합식 발견 순간 | 새 직업이 나오는 순간 놀라거나 기억하는가 |
| ③ | 합성 화면 UX | 합성 가능 여부를 설명 없이 이해하는가 |
| ④ | 합성 후 전투력 차이 체감 | 합성 전·후 전투에서 차이를 느끼는가 |

### 합격 기준 (사전 등록)

> **3명 이상이 합성을 "다시 하고 싶다"고 말하면 통과.**

- 합격 기준은 시험 **전에** 등록한다. 시험 후 기준을 바꾸지 않는다.
- 불합격 시: M4 일정과 합성 규칙(재료 수 곡선·조합식 범위)을 재검토한다.

### 실패 시 대응

- 승급 체감 약함 → ★ 승급 시 외형·능력치 변화 강도 조정.
- 조합식 발견 반응 없음 → 레시피 공개 범위·연출 방식(도감 기록, 화면 효과) 재설계.
- UX 혼란 → 정리 화면 흐름과 합성 가능 표시 방식 재설계.
- 전투력 차이 체감 없음 → 합성 보상(HP·방어 증가폭, 직업 카드 추가)의 수치 조정.

### 연계 이슈

- RUNE-22 G2 관문 (이 시험은 G2 전에 완료)
- RUNE-25 G3 합성 재미 관문 (이 시험이 사전 신호)
- RUNE-24 합성 빈도 시뮬레이션 (수치 근거)
- RUNE-67 레시피표 설계, RUNE-68 레시피 도감 UI

## 2부: 외부 검증 전진 계획 (RUNE-75)

### 목적

지인(G2의 3명)이 아닌 **낯선 사람**에게 가능한 빨리 피드백을 받아, 외부 시선의 문제를 조기에 파악한다.
목표 인원: 낯선 사람 **5~10명** (G2의 지인 3명과 별도).

### 전제 조건

G2(지인 3명 관문) **통과 후** 진행한다.
G2를 통과하지 못하면 카드·에너지·적 예고를 재설계하며, 외부 검증은 그 이후로 미룬다.

### 방법 A — 웹 프로토타입 (itch.io)

| 항목 | 내용 |
|---|---|
| 플랫폼 | itch.io, 무료 공개 |
| 빌드 방식 | Godot 웹 내보내기(HTML5) |
| 조건 | 웹 빌드 가능 시점. GodotSteam은 웹에서 사용 불가이므로 Steam 연동 없이 순수 게임만 |
| 장점 | 설치 없이 바로 플레이 가능, 모집이 쉬움 |
| 단점 | 플랫폼 방향(RUNE-78)이 Steam 네이티브로 확정되면 웹 최적화 비용이 낭비될 수 있음 |

### 방법 B — Steam Playtest (키 방식)

| 항목 | 내용 |
|---|---|
| 플랫폼 | Steam Playtest (키 배포 방식, 공개 상점 페이지 불필요) |
| 조건 | G2 통과 후 Steamworks 가입(RUNE-37) 완료 시점. 앱 등록비 $100 필요 |
| 목표 인원 | 5~10명 |
| 장점 | Steam 환경에서의 실제 체감 확인 가능 |
| 단점 | Steamworks 가입·앱 등록 선행 필요, G2 직후 바로 시작하기 어려울 수 있음 |

### 채택 기준

플랫폼 방향(RUNE-78) 결정 후 채택한다.

- **웹 우선으로 확정** → 방법 A
- **Steam 네이티브 유지** → 방법 B

방향이 미결인 동안에는 A·B 중 먼저 가능한 것을 준비해 두되, 최종 선택은 RUNE-78 결정에 따른다.

### 수집 항목

| 항목 | 설명 |
|---|---|
| 진행불가 버그 | 플레이어가 더 이상 진행할 수 없게 만드는 버그 |
| 튜토리얼 이해도 | 설명 없이 첫 전투를 끝낼 수 있는가 |
| 합성 재미 | 합성(승급·조합식)이 흥미로운가, 다시 하고 싶은가 |
| 전체 인상 | 한 문장 또는 별점 형식의 첫인상 |

### 피드백 파이프라인

```
플레이어 → 구글 폼(간단한 질문 4~6개) → 담당자가 Jira 이슈 등록(RUNE-64 연계)
```

- 구글 폼은 M2 완료 직후 준비한다. 질문은 위 수집 항목을 그대로 쓴다.
- 버그는 RUNE-64(피드백→Jira 파이프라인) 절차에 따라 이슈화한다.
- 피드백 결과는 G3(RUNE-25) 판단 자료로 사용한다.

### 연계 이슈

- RUNE-22 G2 관문 (외부 검증 전진의 전제)
- RUNE-37 Steamworks 가입 (방법 B 전제)
- RUNE-64 피드백→Jira 파이프라인
- RUNE-78 플랫폼 방향 결정 (방법 A·B 채택 기준)
- RUNE-25 G3 합성 재미 관문 (피드백 결과 활용 시점)
