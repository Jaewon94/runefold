# Steam 업적 목록 설계 (RUNE-56, 2026-10-30)

> 정본: Confluence RUNE 스페이스 (페이지 미등록, RUNE-56 완료 시 등록 예정), 마지막 동기화일 2026-10-30

이 문서는 Steam 업적 목록과 기술 요건을 다룬다.
게임 전반 설계는 [design.md](design.md), 직업·티어는 [job-tree-plan.md](job-tree-plan.md), 난이도는 [difficulty-plan.md](difficulty-plan.md) 를 정본으로 삼는다.

상태 표기: **확정** / **잠정** / **미정** / **제안** (design.md 와 같음).

## 1. 설계 원칙

Steam 업적은 플레이어의 참여도와 재방문을 높이고 숨겨진 콘텐츠로 안내하는 역할을 한다. 하드코어 로그라이크에서 업적은 도전감을 주는 동시에 자연스러운 튜토리얼 역할도 한다.

| 원칙 | 내용 |
|---|---|
| **진행형 우선** | 플레이하다 보면 자연히 얻는 업적이 절반 이상이다. 첫 클리어, 첫 합성, 직업 해금 등 이정표마다 하나씩 받는다. 부담 없이 시작할 수 있다는 신호가 된다. |
| **도전형은 선택** | 어렵거나 특이한 조건을 이미 아는 플레이어가 노리는 것이다. 기본 진행을 막아서는 안 된다. |
| **히든은 발견의 기쁨** | 공략을 보지 않아도 발견할 수 있을 만한 희귀 이벤트나 조합에 붙인다. 힌트조차 주지 않고, Steam 에는 설명도 잠근다. |
| **그라인딩 최소화** | "유닛 1000마리 처치" 같은 단순 반복 업적은 만들지 않는다. 횟수 기반이 필요하면 자연 플레이로 달성되는 수치에 맞춘다. |
| **결정론과 일치** | 업적 트리거는 SeededRng 기반 규칙 엔진 이벤트에 연결한다. 재현 가능한 조건에서만 발동해야 한다. |

## 2. 카테고리별 업적 목록 (총 30개 목표)

### 2-1. 진행형 (10개) — 자연스럽게 달성

플레이를 이어 가면 얻는 이정표 업적이다. 클리어나 합성 횟수를 세는 통계(stat) 기반으로 구현한다.

| # | 업적 이름(가칭) | 달성 조건 | 비고 |
|---|---|---|---|
| P01 | 첫 번째 이야기 | 런을 처음 클리어한다 | 마지막 보스 처치 시 발동 |
| P02 | 1막의 끝 | 1막 보스를 처음 처치한다 | — |
| P03 | 세 번의 합 | ★3 유닛을 처음 완성한다 | 승급 이벤트 발동 시 확인 |
| P04 | 별의 다섯째 | ★5 유닛을 처음 완성한다 | — |
| P05 | 전설의 경지 | ★7 유닛을 처음 완성한다 | 곡선 Z 기준 숙련자 중앙값 33판(job-tree-plan.md 12-6) |
| P06 | 숨은 레시피 | 조합식(레시피)을 처음 발견해 도감에 기록한다 | 도감 기록 이벤트 발동 시 확인 |
| P07 | 직업 탐구 I | 직업을 5개 해금한다 | 누적 해금 수 stat |
| P08 | 직업 탐구 II | 직업을 10개 해금한다 | stat 누적, P07 과 같은 stat |
| P09 | 직업 탐구 III | 직업을 20개 해금한다 | stat 누적 |
| P10 | 세계의 절반 | 도감을 50% 이상 채운다 | 직업·유물 도감 합산 또는 직업 도감만: **미결** |

### 2-2. 도전형 (12개) — 선택적 도전

기본 진행과 별개로 노려야 얻는 업적이다. 한 런·한 전투 단위 조건이 많아 그라인딩 없이 도전감을 준다.

| # | 업적 이름(가칭) | 달성 조건 | 비고 |
|---|---|---|---|
| C01 | 완벽한 전투 | 단일 전투에서 유닛을 한 명도 잃지 않고 승리한다 | 전투 종료 시 소대 생존 수 확인 |
| C02 | 운명도 비껴간다 | 명중 확률 80% 이상의 공격이 5회 연속 빗나간 뒤에도 그 전투를 이겨낸다 | 빗나감 연속 카운터 stat; 확률 명중(design.md 「M1 전 결정」)이 필요 조건 |
| C03 | 전설의 증명 | ★7 유닛으로 보스를 처치한다 | 마지막 타격 유닛의 ★ 확인 |
| C04 | 불꽃의 연쇄 | 불꽃 태그 카드만으로 한 턴에 적 3명 이상을 처치한다 | 태그 시너지 확인(design.md 「참고작」) |
| C05 | 소수 정예 | 출전 인원을 4명에서 늘리지 않고(대기석에 추가 인원 없이) 마지막 보스를 처치한다 | 판 내내 출전 4명 유지 |
| C06 | 진짜 하드코어 | 창고를 한 번도 사용하지 않고 ★6 유닛을 완성한다 | 창고 사용 횟수 stat 0 + ★6 완성 |
| C07 | 노 리트라이 | 유닛을 한 명도 잃지 않고 런 전체를 클리어한다 | C01 의 런 전체 버전 |
| C08 | 확률의 역설 | 명중 확률 50% 이하인 공격만으로 한 전투의 적을 모두 처치한다 | 전투 중 발동 공격의 확률 추적 |
| C09 | 두 세계의 만남 | 서로 다른 세계(Realm) 출신의 기본 직업을 재료로 조합식을 완성한다 | 크로스오버 조합식 최초 완성 |
| C10 | 절약의 미학 | 상점을 한 번도 이용하지 않고 런을 클리어한다 | 상점 방문 횟수 stat 0 |
| C11 | 만원 소대 | 출전 8명 전원이 ★3 이상인 상태에서 보스를 처치한다 | 전투 시작 시 소대 스냅숏 확인 |
| C12 | 접힌 세계 | 14개 세계(Realm) 각각에서 직업을 최소 1개씩 해금한다 | 세계별 해금 비트마스크 stat |

### 2-3. 히든 (8개) — 🔒 발견의 기쁨

Steam 업적 화면에서 이름·설명을 잠근다(숨겨진 업적). 공략 없이도 발견할 수 있도록 조건을 지나치게 복잡하게 만들지 않는다. 구체 내용은 스포일러이므로 이 문서에서 공개하지 않는다.

| # | 분류 | 잠금 표시 |
|---|---|---|
| H01 | 특정 희귀 이벤트 발견 | 🔒 |
| H02 | 비밀 조합식 완성 | 🔒 |
| H03 | 엔딩 조건 변형 (조건 A) | 🔒 |
| H04 | 엔딩 조건 변형 (조건 B) | 🔒 |
| H05 | 특정 직업 조합 시너지 달성 | 🔒 |
| H06 | 창고와 관련된 특수 조건 | 🔒 |
| H07 | 도감 특수 기록 달성 | 🔒 |
| H08 | 판 내 특수 연속 이벤트 | 🔒 |

> 히든 업적의 상세 내용은 개발 단계에서 별도 내부 문서로 관리하며 저장소에 올리지 않는다(공개 저장소 규칙).

## 3. Steam 업적 기술 요건

### 3-1. GodotSteam 연동

- Steam 업적은 [GodotSteam](https://godotsteam.com/) 의 `ISteamUserStats` API 로 연동한다.
- 엔진: Godot 4, GDScript (확정, design.md 「기술안」).
- GodotSteam 버전·출처·라이선스·확인일은 도입 시점에 [docs/third-party.md](third-party.md) 에 기록한다.

```gdscript
# 업적 언락 예시 (가칭, 코드 단계 열린 뒤 작성)
Steam.setAchievement("ACH_P01_FIRST_CLEAR")
Steam.storeStats()
```

- 업적 ID 규칙: `ACH_<카테고리><번호>_<SCREAMING_SNAKE>` (예: `ACH_P01_FIRST_CLEAR`, `ACH_C02_FIVE_MISSES`).
- 언락은 규칙 엔진(godot/game/)에서 발동하고, 렌더링·UI 레이어는 알림 표시만 담당한다(규칙-렌더 분리 원칙).

### 3-2. 통계(stat) 기반 진행형

누적 카운터가 필요한 업적(P07~P10, C01~C12 일부)은 `ISteamUserStats` 의 INT stat 을 사용한다.

| stat 이름(가칭) | 타입 | 용도 |
|---|---|---|
| `STAT_JOB_UNLOCKED` | INT | 누적 직업 해금 수 (P07~P09, C12) |
| `STAT_RECIPE_FOUND` | INT | 누적 조합식 발견 수 (P06) |
| `STAT_SHOP_USED` | INT | 런당 상점 이용 횟수 (C10, 런 시작 시 초기화) |
| `STAT_UNIT_LOST` | INT | 런당 유닛 손실 수 (C07, 런 시작 시 초기화) |
| `STAT_MISS_STREAK` | INT | 연속 빗나감 횟수 (C02, 명중 시 초기화) |
| `STAT_CODEX_PCT` | FLOAT | 도감 채움 비율 0.0~1.0 (P10) |
| `STAT_REALM_UNLOCKED` | INT | 비트마스크, 세계별 해금 여부 (C12) |

- stat 은 `storeStats()` 로 Steam 서버에 저장하고 업적 달성 즉시 호출한다.
- 런당 초기화 stat 은 런 시작 이벤트(`run_started`)에서 `resetAllStats(false)` 대신 개별 `setStatInt` 로 0 을 쓴다(다른 누적 stat 보호).

### 3-3. 업적 아이콘 규격

Steam 요건 (2026-10-30 기준, 변경 시 Steam 문서를 따름):
- **달성 아이콘:** 256×256 px, PNG, RGB(A).
- **미달성 아이콘:** 256×256 px, 달성 아이콘을 회색조 처리하거나 별도 제작.
- 파일 크기 상한: 1 MB.
- 업적 30개 × 2장(달성·미달성) = 최대 60장.

룬폴드 아트 방향(도트, 32px 기준, design.md 「아트 방향」)과 아이콘 규격의 차이가 크므로 **검증 단계에서는 임시 도형**을 쓰고, 최종 아이콘 제작 시점은 M5a(콘텐츠 완성) 이후로 잡는다.
