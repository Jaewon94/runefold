# 규칙 엔진 명세 (초안 v0.1, 2026-10-29)

Jira RUNE-82. EGM 1차 시험 지적 8~14([egm-trial-result.md](egm-trial-result.md) 34~40행)에 답하는 문서다. **코드가 아니라 문서**이며, M1 을 시작할 때 이 문서를 보고 규칙 코어를 짠다.
규칙의 근거는 [design.md](design.md)(설계), [paper-prototype.md](paper-prototype.md)(종이 규칙·수치), [roadmap.md](roadmap.md) 4절(기술 기준), [job-tree-plan.md](job-tree-plan.md)·[difficulty-plan.md](difficulty-plan.md)(합성·하드 로그라이크), `AGENTS.md`(코드 규약)다. 어긋나면 그 문서들(정본은 Confluence)이 맞고 이 문서를 고친다.

## 0. 읽는 법

| 표기 | 뜻 |
|---|---|
| **[문서]** | 기존 문서에 있는 규칙을 옮겼다. 괄호 안은 출처(문서 행)와 그 문서의 상태(확정·잠정·가정) |
| **[제안]** | 기존 문서에 없어서 이 문서가 정한 값이다. **확정이 아니다.** 한 줄 근거를 붙인다. G0 종이 판정·M1 구현·사용자 결정으로 바꾼다 |
| **[미정]** | 정하지 않고 비워 둔다. 엔진은 설정값(플래그)으로 받는다 |
| **예 E-xx** | 시험으로 확인할 수 있는 입력 → 기대 출력. 숫자는 이 문서의 규칙으로 **손으로 계산한 값이며 코드로 돌리지 않았다(NOT RUN).** M1 에서 그대로 GUT 시험 사례로 옮긴다 |

- 수치(HP·명중·피해)는 종이 프로토타입의 시작값이다. 값이 바뀌어도 **규칙(계산 순서·판정 방법)은 이 문서를 따른다.**
- 좌표 **[제안]**: 칸은 `(x, y)`, x 는 왼쪽→오른쪽 0~7, y 는 위→아래 0~7. 거리는 맨해튼 거리 `|dx| + |dy|` **[문서]**(paper-prototype 23행).
- 예에서 장애물·유닛을 따로 적지 않은 칸은 비어 있다.

## 2. 상태·행동·결과 계약

### 2-1. 단일 진입점 [제안]
```
Rules.apply(state: BattleState, action: Action) -> ApplyResult { state: BattleState, events: Array[Event] }
Rules.preview(state: BattleState, action: Action) -> Preview     # 읽기 전용, 상태·난수를 바꾸지 않는다
```
- **순수 함수:** 같은 `state` 와 `action` 이면 항상 같은 결과다. 입력 `state` 를 고치지 않고 새 상태를 돌려준다(GDScript 에서는 깊은 복사 뒤 적용).
  근거: 명령→상태+이벤트 구조(roadmap 190)를 함수로 고정하면 되돌리기·재생·자동 대전·시험이 모두 같은 길을 쓴다.
- **난수 상태는 `state` 안에 있다.** 스트림별 SeededRng 상태 4단어(`get_state()`)를 상태의 일부로 들고 다닌다. 그래서 `apply` 가 난수를 써도 순수 함수다.
- **엔진 API 금지:** 규칙 코어는 `Node`·`SceneTree`·입력·시간·파일 API 를 부르지 않는다(13절). 화면(`godot/ui/`)은 이벤트 목록을 받아 연출만 한다.
- **거부:** 규칙에 맞지 않는 행동은 상태를 바꾸지 않고(난수 포함) `action_rejected{reason}` 이벤트 1개만 돌려준다.
- **정수만:** 상태와 규칙 계산은 정수·문자열·배열·사전만 쓴다. 부동소수점을 쓰지 않는다. 근거: JSON 왕복과 플랫폼 간 결과가 정확히 같아야 한다.

### 2-2. 상태(전투) [제안, 필드 이름은 구현 때 바꿀 수 있음]
| 필드 | 내용 |
|---|---|
| `rules_version` | 규칙 버전 정수. 재생 호환 판단(12절) |
| `grid` | 8×8 [문서](design 32 확정). 칸 종류: 빈 칸, 장애물(통과 불가·엄폐 제공). 고저차 없음 [문서] |
| `units` | 인스턴스 ID 순 배열. `id, side(ally/enemy), def_id, star, pos, hp, max_hp, move, defense, shield, status{}, moved, downed` |
| `deck` | `draw_pile, hand, discard_pile` (카드 인스턴스 ID 배열) |
| `energy` | 이번 턴 남은 에너지 |
| `phase` | `player_turn / enemy_turn / won / lost` |
| `round` | 라운드 번호(1부터) |
| `moves_locked` | 이번 턴에 카드를 1장이라도 썼는가 |
| `intents` | 적 ID → `{target_id, card/attack, preview_hit_n}` |
| `rng` | 스트림 이름 → 상태 4단어 |
| `config` | 변형 플래그: `commander_id`(변형 C), `tick_counter`(변형 T), `death_variant`(V1/V2/V3) [문서: paper 33·87~98, 시험용 변형] |

### 2-3. 행동(Action) [제안]
| 행동 | 인자 | 거부 사유 예 |
|---|---|---|
| `move` | `unit_id, to` | `already_moved`, `moves_locked`, `out_of_move`, `blocked`, `out_of_bounds` |
| `cancel_move` | `unit_id` | `not_moved`, `moves_locked` |
| `play_card` | `card_id, actor_id, target(칸 또는 유닛), line(h_first/v_first, 선택), push_dir(선택)` | `not_in_hand`, `no_energy`, `wrong_job`, `out_of_range`, `invalid_target`, `actor_downed` |
| `end_turn` | 없음 | `not_player_turn` |
| 런 단계 행동 | `merge`, `craft`, `stash` 등(10절) | `need_3`, `tier_mismatch`, `no_recipe` |

모든 행동은 `phase` 가 맞지 않으면 `battle_over` 또는 `not_player_turn` 으로 거부한다.

### 2-4. 결과(Event) [제안]
사전 `{ "t": 종류, ...필드 }`. 목록 순서가 곧 일어난 순서이며 결정론의 일부다(같은 입력 → 같은 목록·같은 순서).
`turn_started, cards_drawn, deck_shuffled, energy_set, unit_moved, move_cancelled, moves_locked, card_played, energy_spent, hit_rolled{roll, need, hit}, damage_dealt{target, raw, shield_absorbed, defense_reduced, final, hp_after}, shield_gained, shield_expired, healed, pushed, push_blocked, unit_downed, unit_perma_dead{unit_id, side}, intent_set, intent_changed, enemy_acted, battle_won, battle_lost, action_rejected{reason}`.

> `unit_perma_dead` 는 `unit_downed` 직후 반드시 따라온다. 아군이면 런에서 영구 손실, 적이면 격자에서 제거된다(9절). 이 이벤트의 순서가 결정론의 일부다.

**E-01** 상태 S 에서 기사가 이동하지 않은 상태로 `move(knight, (9,0))` → `[action_rejected{reason: out_of_bounds}]`, 반환 상태는 S 와 같고 `S.rng` 도 같다.

## 3. 턴 흐름·이동·손패

1. **내 턴 시작** [문서](paper 21, 29): 의도를 정하고(8절) 카드 5장을 뽑고 에너지 3 을 얻는다. 덱이 비면 버린 카드를 섞어 덱으로 만든다. 순서 [제안]: `shield_expired → intent_set → cards_drawn → energy_set`.
2. **이동** [문서](paper 22, design 21·33): 유닛마다 한 번, 상하좌우 칸 수가 이동력 이하, 장애물·유닛(쓰러진 토큰 포함) 통과 불가. 이동은 공짜다.
   - [제안] 이동 가능 여부는 최단 경로 길이(BFS)로 판정하고, 도착 칸은 비어 있어야 한다. 근거: 사거리와 같은 맨해튼 감각을 유지하면서 장애물 우회를 정확히 센다.
   - [제안] 취소는 유닛 단위(`cancel_move`)이며, 취소한 유닛은 원래 칸으로 돌아가고 다시 이동할 수 있다. 어느 유닛이든 카드를 1장 쓰면 `moves_locked` 가 되어 그 턴의 모든 이동이 확정된다 [문서](paper 22).
   - 이동·취소는 난수를 쓰지 않는다.
3. **카드** [문서](paper 23): 에너지만큼, 직업 태그가 맞는 유닛이 실행한다.
4. **턴 끝** [문서](paper 24): 남은 손패는 버리고 에너지는 이월하지 않는다. 그다음 적 턴(8절).

**E-02** 기사(이동 3) (0,0). `move(knight,(2,1))` → 경로 길이 3, `unit_moved`. 다른 상태에서 `move(knight,(3,1))` → 길이 4, `out_of_move`.
**E-03** 장애물 (1,0)·(1,1)·(1,2), 기사 (0,0) 이동 3. `(2,0)` 까지 최단 경로는 (0,0)→(0,3)→(2,3)→(2,0) 으로 길이 8 > 3 → `out_of_move`(맨해튼 거리는 2 지만 경로로 판정).
**E-04** 기사 (0,0)→(1,0) 이동, 레인저 이동, 기사가 `베기` 사용 → `moves_locked`. 이어서 `cancel_move(ranger)` → `action_rejected{moves_locked}`.
**E-05** 덱 0장, 버린 카드 12장, 내 턴 시작 → `deck_shuffled`(deck 스트림 사용) 뒤 5장 뽑기. 손패 5, 덱 7.

**덱 고갈 시 자동 섞기 규칙 [문서](paper 21~24) [제안 보완]:** 뽑기가 필요한 모든 시점(턴 시작·사망 유닛 카드 처리)에서 `draw_pile` 이 비어 있으면, 뽑기 전에 `discard_pile` 전체를 `deck` 스트림으로 섞어 `draw_pile` 로 옮기고 `deck_shuffled` 이벤트를 낸다. 섞고 나면 `discard_pile` 은 비어 있다. `discard_pile` 도 비어 있으면 섞기 없이 `draw_pile` 은 그대로 빈 상태다(E-27 참고). 이 규칙은 한 번의 뽑기 단계 안에서 최대 1회만 일어나며, 섞기 후에도 카드가 없으면 `draw_stopped` 없이 빈 손패를 허용한다.

## 4. 명중

### 4-1. 산식
- **[문서]**(paper 26~27, 시작값; design 34 확정 "표시 확률은 항상 정확"): 명중 수치 N, `d10 ≤ N` 이면 명중. 표시 확률 = `N × 10%`.
- **계산 순서 [제안]:** `N = clamp(카드 명중 + 보정 합, 1, 9)`. 보정: 축복 +2 [문서](paper 49), 엄폐 −3 [문서](paper 26). 모든 보정을 더한 **뒤에** 한 번만 자른다. 근거: 순서에 따라 결과가 달라지지 않게 하는 흔한 방법이다.
- **굴림 [제안]:** `roll = combat 스트림.int_range(1, 10)`, `hit = roll <= N`. 근거: 1~10 균등이면 표시 `N×10%` 가 정확히 참 확률이다. `chance()`·`next_float()` 은 규칙 판정에 쓰지 않는다(정수만).
- **표시 단위 [제안]:** 10% 단위 정수(`10%`~`90%`). 숨은 보정(연속 빗나감 보정, 난이도별 몰래 보정)을 두지 않는다. 근거: "표시 확률은 정확"(design 34)과 "조작이 아니라 풀 구성"(difficulty-plan 25).
- 적 명중 기본 7(오크 8), 아군이 엄폐면 −3 [문서](paper 30·58~61).

### 4-2. 공격선과 엄폐(시야)
- **[문서]**(paper 26): 같은 행·열이면 그 직선, 아니면 두 꺾은 경로 중 공격자가 고른 쪽. **목표에 인접한 칸**이 공격선 위 장애물이면 엄폐. 사거리 1 공격은 엄폐가 없다.
- **목표 바로 앞 칸 C [제안, 문서 규칙을 계산식으로 옮김]:** 공격자 A, 목표 T.
  - `h_first`(가로 먼저): `ty ≠ ay` 이면 `C = (tx, ty − sign(ty − ay))`, 아니면 `C = (tx − sign(tx − ax), ty)`.
  - `v_first`(세로 먼저): `tx ≠ ax` 이면 `C = (tx − sign(tx − ax), ty)`, 아니면 `C = (tx, ty − sign(ty − ay))`.
  - C 가 장애물이면 엄폐 −3.
- **기본 선택 [제안]:** 행동에 `line` 이 없으면 엔진이 N 이 큰 쪽을 고르고, 같으면 `h_first`. 적은 항상 자기에게 유리한 쪽을 쓴다. 근거: 플레이어가 손해 보는 선택을 실수로 하지 않게 한다.
- **시야 차단 없음 [제안]:** 공격선 중간(목표 바로 앞이 아닌 칸)의 장애물·유닛은 공격을 막지 않는다. 근거: 종이 규칙에 차단 규칙이 없고, 8×8 에서 차단까지 넣으면 계산이 무거워진다. G0 뒤 다시 본다.
- 사거리는 맨해튼 거리 ≤ 카드 사거리 [문서](paper 23).

**E-06** 레인저 (0,0) `사격`(사거리 5, 명중 8) → 고블린 (3,2), 장애물 (3,1). 거리 5 OK. `h_first` 의 C=(3,1) 장애물 → N=5(50%). `v_first` 의 C=(2,2) 빈 칸 → N=8(80%). `line` 없이 미리보기 → `v_first`, 80%.
**E-07** 같은 행: 레인저 (0,4) → 고블린 (4,4), 장애물 (3,4) → N=5(50%). 장애물이 (2,4) 에만 있으면 → N=8(80%)(시야 차단 없음).
**E-08** 자르기: `화염구` 9 + 축복 2 = 11 → N=9(90%). `속사` 6 − 엄폐 3 = 3(30%). 명중 2 카드 − 엄폐 3 = −1 → N=1(10%).
**E-09** 굴림: N=8 에서 `roll` 이 8 이면 명중, 9 면 빗나감. (시험에서는 굴림 값을 알 수 있는 시드를 고르거나 `hit_rolled` 의 `roll·need·hit` 이 `hit == (roll <= need)` 를 만족하는지 본다.)

## 5. 피해·방어 (카드 방어 vs 스탯 방어)

| | 스탯 방어 | 카드 방어(막) |
|---|---|---|
| 출처 | 유닛 스탯 [문서](design 38 확정) | `방패 올리기` 같은 카드 [문서](paper 40) |
| 수명 | 영구(전투 내내) | [문서] "다음 적 턴까지". [제안] 내 다음 턴 시작에 0 으로 사라진다(`shield_expired`) |
| 작동 | 피해 한 번마다 그만큼 뺀다. 줄지 않는다 | 피해에서 먼저 빠지고, 뺀 만큼 막이 줄어든다 |
| 겹침 | 해당 없음 | [제안] 더한다(막 4 + 막 4 = 8). 근거: 카드 두 장을 쓴 대가가 보이게 한다 |

**산식 [문서](paper 18 "막 → 방어 → 최소 1"):**
```
absorbed = min(shield, raw);  shield -= absorbed
after_def = max(0, raw - absorbed - defense)
final = max(1, after_def)          # 문서 그대로: 어떤 피해든 최소 1
hp = max(0, hp - final)
```
- 피해는 고정값이다(카드가 정함, [문서] paper 39~50). [제안] 피해에 난수 범위를 두지 않는다. 근거: 난수는 명중 한 곳에만 두어야 억울함의 원인을 하나로 추적할 수 있다.
- **해석 주의(사용자 판단 필요):** 문서를 글자 그대로 읽으면 막이 피해를 전부 흡수해도 1 이 들어간다(E-11). 대안은 "막이 다 흡수하면 0, 최소 1 은 막 뒤 남은 피해가 있을 때만"이다. 이 문서는 **문서 그대로**를 기본으로 두고, 엔진은 `min_damage_after_full_block`(1 또는 0) 설정으로 받는다.
- [제안] 한 카드의 "피해 +2"(밀치기 막힘)는 별도 피해가 아니라 같은 한 번의 `raw` 에 더한다. 근거: 방어·최소 1 이 두 번 적용되는 것을 막는다.

**E-10** `베기`(4) → 방패병(방어 2, HP 10) 명중 → final 2, HP 8.
**E-11** 고블린 공격(3) → 기사(방어 1, 막 4) → absorbed 3, 막 1 남음, after_def 0, **final 1**, HP 14→13. (대안 설정 0 이면 HP 14.)
**E-12** 오크 공격(5) → 기사(방어 1, 막 0) → final 4, HP 14→10.
**E-13** 오크 공격(5) → 기사(방어 1, 막 4) → absorbed 4, 막 0, after_def 0, final 1.
**E-14** 기사가 막 4 를 얻고 적 턴에 피격 없음 → 내 다음 턴 시작에 `shield_expired`, 막 0.

## 7. 승리·패배

- **[문서]** 적 전멸 = 승리, 아군 전멸 = 패배(paper 16; 패배 조건은 design 35 "가정"). 변형 C: 주 지휘관이 쓰러지면 즉시 패배(paper 97).
- **판정 시점 [제안]:** 피해 하나를 처리해 `unit_downed` 가 나올 때마다 바로 판정한다. 끝나면 `battle_won`/`battle_lost` 를 내고 `phase` 를 바꾸며, 남은 효과(예: 화염구의 남은 주변 피해)는 **끝까지 처리한 뒤** 판정한다(한 카드 안은 원자적). 그 뒤 모든 행동은 `battle_over` 로 거부. 근거: 한 카드의 결과가 판정 시점 때문에 반쯤 잘리지 않게 한다.
- **동시 전멸 [제안]:** 한 카드로 마지막 적과 마지막 아군이 함께 쓰러지면 **패배**. 근거: 아군이 하나도 없으면 런을 이어 갈 수 없다.
- **아군 전원 사망 시 즉시 패배 [제안]:** `unit_perma_dead` 이벤트가 발생한 직후, 살아 있는 아군 유닛(`downed == false`, `side == ally`)이 하나도 없으면 한 카드의 남은 효과와 무관하게 즉시 `battle_lost` 를 내고 `phase` 를 `lost` 로 바꾼다. 이후 모든 행동은 `battle_over` 로 거부한다. 이 검사는 적의 `unit_perma_dead` 에서는 하지 않는다(적 전멸은 `battle_won` 으로 처리). 근거: 아군이 전멸했으면 남은 카드 효과를 이어 처리할 필요가 없고, 동시 전멸 시 패배 우선순위(위 항목)와 일관된다.
- 변형 T(틱 카운터)·V2·V3 은 `config` 플래그로만 켠다 [문서](roadmap 297 "기본에서 제외").

**E-19** 적이 고블린 1(HP 2) 남음, 기사 `베기` 명중 → `damage_dealt`, `unit_downed`, `battle_won`. 이어서 `play_card` → `action_rejected{battle_over}`.
**E-20** 마법사(HP 2, 마지막 아군) (3,4) 가 `화염구` 로 인접 고블린(HP 5, 마지막 적) (3,5) 명중 → 고블린 HP 0, 마법사 주변 피해 2 → HP 0 → `battle_lost`(동시 전멸).
**E-21** 변형 C, 주 지휘관 기사 HP 0, 다른 아군 3명 생존 → `battle_lost`.

## 8. 적 AI·의도(예고)·재계산

- **의도 결정 [문서](paper 29):** 내 턴 시작에 각 적은 가장 가까운 아군을 목표로 삼는다. 동률이면 HP 낮은 쪽.
  - [제안] "가까움"은 맨해튼 거리(장애물 무시). 근거: 종이에서 사람이 바로 셀 수 있고 사거리 규칙과 같은 척도다.
  - [제안] 그래도 동률이면 유닛 ID 가 작은 쪽. 근거: 결정론에 난수가 필요 없게 한다. **AI 는 난수를 쓰지 않는다.**
- **의도에 보여 주는 것 [제안]:** 목표, 공격 피해, 그리고 "적이 지금 움직인다면" 의 예상 명중(N×10%). 예상 명중은 `preview` 로 계산하며 난수를 쓰지 않는다.
- **재계산 시점 [제안]:** 목표는 내 턴 동안 고정이다. 다음 경우에만 바뀐다 — ① 목표가 쓰러짐 → 그 즉시 남은 아군 중 다시 고름(`intent_changed`) [문서 "다음으로 가까운 아군"(paper 30)을 즉시 적용] ② 도발 [문서](paper 41). 예상 명중 숫자는 내 행동이 끝날 때마다 다시 계산한다(목표가 엄폐로 이동하면 숫자가 바뀜). 근거: 예고가 거짓이 되지 않게(difficulty-plan 22).
- **적 턴 [문서](paper 30):** 목표를 향해 이동한 뒤 사거리 안이면 공격. [제안] 행동 순서는 적 ID 오름차순.
- **이동 칸 고르기 [제안]:** 이동력 안에서 갈 수 있는 칸(현재 칸 포함, BFS) 중
  1. 목표를 사거리 안에 두는 칸이 있으면: 명중 N 최대 → 이동 거리 최소 → (y, x) 사전순.
  2. 없으면: 목표까지 BFS 거리(유닛·장애물 우회)가 가장 짧은 칸 → 이동 거리 최소 → (y, x) 사전순.
  근거: "더 잘 맞히는 자리"를 찾는 전술 게임 AI 의 흔한 기본형이면서, 종이에서 사람이 따라 할 수 있다.
- 공격 굴림은 아군 공격과 같은 combat 스트림을 쓴다.

**E-22** 적 고블린 (7,7). 아군 기사 (4,7)(거리 3, HP 14), 레인저 (7,3)(거리 4) → 목표 기사. 마법사가 (7,4)(거리 3, HP 8) 에 있으면 → 목표 마법사(동률, HP 낮음).
**E-23** 고블린 (7,7) 이동 3, 목표 기사 (4,7), 근접(사거리 1). 기사에 인접하고 갈 수 있는 칸: (5,7)(이동 2), (4,6)(이동 4, 불가) → (5,7) 로 가서 N=7(70%) 공격.
**E-24** 궁수 (7,0) 이동 2, 사거리 4, 목표 레인저 (2,0), 장애물 (3,0). 후보: (6,0)(이동 1, 거리 4, C=(3,0) 엄폐 → N=4), (5,0)(이동 2, N=4). 다른 칸은 사거리 밖 → (6,0), 40%.
**E-25** 내 턴에 고블린의 목표 기사가 아군 화염구 주변 피해로 쓰러짐 → 즉시 `intent_changed` 로 남은 가장 가까운 아군.

## 9. 사망·쓰러진 유닛의 카드

- **[문서]**(design 35 확정, paper 32~33): HP 0 이 되면 그 판에서 영구 손실. 쓰러진 아군은 토큰을 그 칸에 두며 통과 불가.
- [제안] 적은 쓰러지면 격자에서 사라진다(통과 가능). 근거: 종이 문구가 아군 영구 손실 절에 있고, 시체가 쌓이면 8×8 이 막힌다. **사용자 확인 필요.**
- **쓰러진 유닛의 직업 카드 [문서, 임시](paper 33):** 뽑는 즉시 버리고 1장 다시 뽑는다(에너지 없음). 같은 직업의 다른 유닛이 살아 있으면 쓸 수 있는 카드로 본다 [제안].
- **종료 조건 [제안]:** 한 번의 뽑기 단계에서 쓸 수 없는 카드를 버린 횟수가 그 단계 시작 때의 `덱 + 버린 카드` 장수에 이르면 더 뽑지 않고 손패를 5장보다 적게 둔다(`draw_stopped`). 근거: 덱이 쓸 수 없는 카드만 남았을 때 무한 반복을 막는다(EGM 지적 16).

**E-26** 덱 위 순서 [베기(기사 사망), 사격, …], 기사 외 기사 없음 → 베기 버림, 사격 손패. 에너지 변화 없음.
**E-27** 내 턴 시작에 덱 2장·버린 카드 0장이고 둘 다 쓰러진 기사의 카드(한도 2) → 1장 뽑아 버림, 1장 뽑아 버림 → 버린 횟수 2 = 한도 → `draw_stopped`, 손패 0, 섞기 없음.

**창고 유닛과 전투의 관계 [제안]:** 창고에 맡긴 유닛(`stashed: true`)은 출전 소대에 없으므로 전투 격자에 배치되지 않는다. `battle_lost`/`battle_won` 판정 시 창고 유닛의 생사는 반영하지 않는다. 전투 중 발생한 `unit_perma_dead` 가 창고 유닛에 영향을 주지 않는다. 근거: 창고는 "그 런에서 쓰지 않는다"(difficulty-plan 42)이며, 합성 재료도 될 수 없다(10-1).

## 10. 합성 상태 전이 (승급·조합식)

합성은 전투 밖 정리 화면에서만, 플레이어가 확정할 때 일어난다 [문서](design 53 잠정). **합성은 난수를 쓰지 않는다** [제안].

### 10-1. 승급 (같은 것 3 → 1)
- **[문서]**(design 49~53, job-tree-plan 97~98): 이름과 단계가 모두 같은 3개만. 결과는 한 단계 위 직업(이름·외형·스킬 변경), 직업 카드 1장 덱에 추가, HP·방어 상승(잠정), 등급(희귀도) 불변. ★5~★7 은 특수 재료·조건 추가 [문서, 방향 확정·세부 미정].
- 소모 개체에서 결과로 넘어가는 것 [제안]:

| 항목 | 규칙 [제안] | 근거 |
|---|---|---|
| 인스턴스 | 재료 3개를 지우고 새 ID 1개를 만든다. 기록용 `merged_from`(재료 ID 3개) | 저장·로그에서 계보를 추적 |
| HP | 결과 `hp = 새 직업 max_hp`(가득) | 자동 전투·합성 게임의 흔한 관행이 "새 개체로 태어남"이다. 런 사이 HP 이월 여부가 미정이어도 같은 규칙으로 쓸 수 있다 |
| 덱 카드 | 덱의 카드는 유닛 소유가 아니다. 재료의 기존 카드는 그대로 남고, 새 직업 카드 1장만 더한다 | 소대 공유 덱(design 36 확정)과 맞음 |
| 직업 태그 | 승급 직업은 계보 아래 직업의 태그를 함께 가진다(근위기사는 `기사` 카드도 씀) | 승급 뒤 기존 카드가 죽은 카드가 되지 않게 |
| 장비 | 재료의 장비는 모두 런 보관함으로 돌아간다(사라지지 않음). 결과는 장비 없이 시작 | 자동 전투 장르의 "합쳐도 아이템은 잃지 않는다" 관행. **장비 체계 자체가 미정**(유물 형태: 장착형 vs 런 전역, roadmap 81) |
| 상태·버프 | 전투 밖이라 없음. 영구 강화가 생기면 셋 중 가장 큰 값을 남긴다(미정) | |
| 주 지휘관 | 재료 중 하나가 주 지휘관이면 결과가 주 지휘관 | 변형 C 가 합성으로 깨지지 않게 |
| 창고 | 창고에 맡긴 유닛은 재료가 될 수 없다 | 맡긴 유닛은 그 런에서 쓰지 않는다(difficulty-plan 42) |
| 재료 위치 | 출전·대기석 어디서든 재료가 될 수 있고, 결과는 첫 번째 재료(ID 가 가장 작은 것)의 자리에 놓인다 | 화면에서 결과 위치가 예측되게 |

- **카드 승급 [문서](design 15·50):** 같은 이름·같은 Lv 카드 3장 → 1장 Lv+1. 덱이 2장 줄어든다. 카드 Lv 의 상한과 효과는 [미정](design 51).

**E-28** 기사★1 ID 4(HP 14/14), 7(9/14), 9(14/14) `merge` → 재료 삭제, 새 ID 21, ★2 위 직업(가칭 근위기사, 계보 미정), HP = 새 최대 HP, `merged_from=[4,7,9]`, 덱 20 → 21장, 등급 일반 → 일반.
**E-29** 기사★1 2개 + 기사★2 1개 → `tier_mismatch`. 기사★1 2개만 → `need_3`. 기사★1 3개 중 1개가 창고에 있음 → `stashed_material`.
**E-30** 재료 7 이 장비 A, 9 가 장비 B → 합성 뒤 보관함 `[A, B]`, 결과 장비 없음.
**E-31** 덱에 `베기` Lv1 3장 → `베기` Lv2 1장, 덱 20 → 18장.

### 10-2. 조합식 (서로 다른 재료 2~3 → 새것)
- **[문서]**(design 54 잠정): 유닛·카드 대상(유물 제외), 고정 레시피표, 일부 공개·나머지 발견 시 도감 기록, 결과는 재료 단계와 무관하게 ★1(Lv1).
- [제안] 재료 ★ 하한 없음. 다만 ★2 이상 재료가 있으면 결과 미리보기에 "투자한 단계가 사라진다" 경고 플래그(`loses_tier: true`). 근거: 문서가 "재료 단계와 무관"이라 했으므로 막지 않되 실수는 막는다.
- [제안] 결과 등급은 레시피표에 적는다(재료 등급이 서로 다를 수 있으므로). HP 는 가득, 덱은 "새 유닛을 얻을 때"와 같은 규칙(이 문서 제안: 그 직업 카드 1장 추가 — **새 유닛 획득 시 카드 규칙은 문서에 없다**). 장비·지휘관·창고 처리는 10-1 표와 같다.
- [제안] 크로스오버 결과는 재료 직업들의 태그를 모두 가진다. 근거: 재료가 사라져도 덱의 그 직업 카드가 죽은 카드가 되지 않게 한다. 밸런스 영향이 커서 **사용자 판단 필요**.
- [제안] 레시피는 재료 `def_id` 의 정렬된 목록으로 찾는다(순서 무관). 표에 없으면 `no_recipe`, 상태·도감 변화 없음. 처음 성공하면 메타의 도감에 레시피 ID 를 기록한다.
- ★1 로 시작한 크로스오버가 이후 승급 계보를 갖는지는 [미정](job-tree-plan 126).

**E-32** 기사★2(ID 21) + 검객★1(ID 30), 레시피 `기사+검객 → 철갑 검협`(가칭) → 재료 삭제, 새 ID 31 철갑 검협★1, HP 가득, `loses_tier: true` 였음, 덱 +1, 도감에 레시피 기록(처음이면).
**E-33** 마법사 + 탐정(표에 없음) → `no_recipe`, 상태·도감·난수 변화 없음.

## 11. 결정론·난수

- **[문서]**(AGENTS 33~35, roadmap 191·203): 규칙 코드는 `godot/game/rng/seeded_rng.gd` 의 `SeededRng`(xoshiro128** + splitmix32)만 쓴다. `randi`·`randf`·`randi_range`·`randf_range`·`randomize`·`seed`·`RandomNumberGenerator`·배열 `.shuffle()`·`.pick_random()`·`rand_from_seed` 금지. 감시 시험이 `res://game` 을 검사한다. "난수 방식과 호출 순서"는 나중에 바꾸기 어려운 것이다.
- **같은 시드 = 같은 결과 [제안, 문서 원칙을 계약으로 적음]:** 같은 `rules_version`, 같은 런 시드, 같은 행동 목록이면 이벤트 목록이 바이트 단위로 같다(사전 키 정렬 JSON 기준).
- **미리보기는 난수를 쓰지 않는다 [제안]:** `preview`·의도 표시·사거리 표시·합성 미리보기는 상태를 읽기만 한다. 명중은 확률(N)을 계산할 뿐 굴리지 않는다. 근거: 미리보기 횟수가 결과를 바꾸면 "표시 확률은 정확"(design 34)이 깨진다.
- **스트림 분리 [제안]:** 용도별 SeededRng 를 따로 둔다. 근거: 상점을 한 번 더 열거나 지도 노드를 다르게 고른 일이 전투 굴림 순서를 밀어내지 않게 한다(원인 추적과 재현이 쉬워짐).

| 스트림 | 쓰는 곳 |
|---|---|
| `deck` | 덱 섞기 |
| `combat` | 명중 굴림(아군·적 공통) |
| `map` | 층 지도 생성 |
| `reward` | 전투 보상 |
| `shop` | 상점 진열 |
| `event` | 이벤트 노드 |
| `ai` | 예약(지금 AI 는 난수를 쓰지 않음) |

- **스트림 만들기 [제안]:** `master = SeededRng.new(run_seed)`. 위 표의 순서대로 스트림마다 `hi = master.next_u32()`, `lo = master.next_u32()`, `SeededRng.new((hi << 32) | lo)`. **새 스트림은 표 끝에만 추가**한다(앞 스트림 시드가 바뀌지 않게). 스트림은 런 하나 동안 이어진다.
- **되돌리기 [제안, RUNE-46 결정 대상]:** 난수를 쓰지 않은 행동(이동·취소)만 되돌릴 수 있다. 근거: 굴림 뒤 되돌리기는 결과를 보고 다른 선택을 하는 "미래 엿보기"가 된다. 저장 후 다시 불러와도 난수 상태가 저장돼 있어 같은 행동은 같은 결과다.

**E-34** 상태 S 에서 `preview(play_card 사격)` 를 100번 → 매번 같은 N, `S.rng` 상태 4단어가 호출 전과 같다. 그 뒤 `apply` 결과는 미리보기를 한 번도 안 한 경우와 같다.
**E-35** 같은 런 시드·같은 행동 목록으로 전투를 두 번 → 이벤트 JSON(키 정렬) 해시가 같다.
**E-36** 상점 화면에서 진열을 만든 경우와 만들지 않은 경우 → 다음 전투의 `hit_rolled.roll` 순서가 같다(`shop` 과 `combat` 이 독립).
**E-37** 전투 중 행동 k 개 뒤 저장 → 불러오기 → 나머지 행동 → 저장 없이 끝까지 간 경우와 최종 상태·이벤트가 같다.

## 12. 저장 스키마·버전·마이그레이션

- **[문서]**(roadmap 193): JSON + `schema_version` + 마이그레이션, 외부 .tres 를 세이브로 쓰지 않는다. 저장 시점(전투 중 vs 노드 사이)과 명령 기록 재생형은 RUNE-46 에서 정한다(미정). 세이브 마이그레이션 시험은 M5.9(roadmap 349).
- **파일 둘 [제안]:** `run.json`(현재 런, 런이 끝나면 지움)과 `meta.json`(도감·직업 해금·창고, 런을 넘어 남음). 근거: 런 사이에 남는 것(difficulty-plan 30·38)과 사라지는 것을 파일로 갈라 실수로 이월되지 않게 한다.
- **전투 중 저장 [제안]:** 전투 시작 스냅숏 + 그 뒤의 행동 목록. 불러오면 스냅숏에서 행동을 다시 적용한다. 근거: 결정론 엔진에서 흔한 "명령 기록 재생" 방식이고 저장 파일이 작으며 재현 시험과 같은 길을 쓴다. `rules_version` 이 다르면 재생 결과가 달라질 수 있으므로 그 전투를 **처음부터 다시 시작**한다(진행 손실을 알린다).
- **값 규칙 [제안]:** 런 시드(GDScript `int` 와 같은 부호 있는 64비트)는 **문자열**로 저장한다(JSON 숫자는 2^53 를 넘으면 값이 깨진다). 난수 상태 4단어(32비트)는 숫자로 저장하고 읽을 때 `int` 로 바꾼다. 정적 데이터는 안정적 문자열 ID(`job.knight`, `card.slash`)로, 인스턴스는 런 상태 안 카운터가 주는 정수 ID 로 참조한다(엔진이 만드는 UID 를 쓰지 않음).
- **버전·마이그레이션 [제안]:** `schema_version` 은 정수, 1부터. `migrate_v{n}_to_v{n+1}(dict) -> dict` 순수 함수를 차례로 적용한다. 더 높은 버전(미래) 파일은 읽지 않고 오류로 알린다. 낮추기(다운그레이드)는 하지 않는다. 버전마다 고정 예시 파일을 시험 자료로 둔다.

```json
{
  "schema_version": 1,
  "rules_version": 1,
  "game_version": "0.0.0",
  "run": {
    "seed": "1234567890123456789",
    "rng": { "deck": [1, 2, 3, 4], "combat": [5, 6, 7, 8] },
    "next_instance_id": 32,
    "act": 1, "node": 3,
    "squad": [ { "id": 21, "def_id": "job.knight_guard", "star": 2, "hp": 16, "merged_from": [4, 7, 9] } ],
    "bench": [], "deck": [ { "id": 101, "def_id": "card.slash", "lv": 1 } ],
    "relics": [], "inventory": [], "gold": 0
  },
  "battle": { "start_snapshot": { }, "actions": [ { "t": "move", "unit_id": 21, "to": [2, 1] } ] }
}
```
(`meta.json` 은 `schema_version`, `codex`(발견한 레시피·직업), `unlocks`, `stash` 를 가진다. 숫자는 예시다.)

**E-38** v1 파일(유닛에 `stashed` 필드 없음) → `migrate_v1_to_v2` → 모든 유닛에 `"stashed": false` 가 붙고 `schema_version` 2. 같은 입력을 두 번 돌려도 결과가 같다.
**E-39** `schema_version` 이 지원 최대보다 큰 파일 → 불러오기 거부, 파일을 고치지 않는다.
**E-40** 시드 `"9223372036854775807"`(2^63−1, GDScript int 최대) 저장 → 불러오기 → 같은 문자열, 같은 스트림 상태.
**E-41** 전투 중 저장 파일의 `rules_version` 이 1, 현재 2 → 전투를 시작 스냅숏에서 다시 시작, 행동 목록 버림, 알림 이벤트.

## 13. 규칙 코드 위치 규약

- **[문서]**(AGENTS 32~35): 규칙 코드는 `godot/game/` 아래. 엔진 난수 감시 시험(`godot/tests/unit/test_no_engine_rng.gd`)이 `res://game` 만 검사하므로 **규칙 코드를 다른 곳에 두면 감시를 벗어난다.** 화면 코드는 `godot/ui/`.
- **하위 배치 [제안]:**

| 경로 | 내용 |
|---|---|
| `godot/game/rng/` | `SeededRng`(이미 있음), 스트림 묶음 |
| `godot/game/core/` | 상태·행동·이벤트 정의, `Rules.apply`/`preview` |
| `godot/game/battle/` | 격자·이동·명중·피해·카드 효과·적 AI·덱 |
| `godot/game/merge/` | 승급·조합식·레시피 조회 |
| `godot/game/run/` | 지도·보상·상점(M3) |
| `godot/game/save/` | 직렬화·마이그레이션 |
| `godot/data/` | 카드·유닛·유물 정적 데이터(.tres, roadmap 192). 규칙 코드는 ID 로만 참조 |
| `godot/tests/unit/` | 규칙 단위 시험 |
| `godot/tests/replay/`, `godot/tests/fixtures/` | 재현(골든) 시험과 고정 자료(세이브 예시 등) |

- **규칙 코드가 쓰지 않는 것 [제안]:** `Node`·`get_tree()`·`Input`·`Time`·`OS` 시각 함수·파일 입출력(저장은 `save/` 가 사전을 만들고 실제 쓰기는 `ui/` 쪽이 한다)·부동소수점 판정. 근거: 시각·장면 트리에 기대면 헤드리스 재현이 깨진다. 감시 시험에 이 항목들을 추가하는 것을 제안한다(시험 코드 변경은 코드 단계가 열린 뒤).

## 14. 헤드리스 시험 방침

- **[문서]**(AGENTS 36, roadmap 159·186): `scripts/run_tests.sh`(헤드리스 GUT 9.7.1, 종료 코드 0 = 통과), CI 통과가 병합 조건, 병합 기준은 "시험 + 시드 재현 + 사용자 플레이 확인".
- **시험 종류 [제안]:**
  1. **규칙 단위 시험:** 이 문서의 예 E-01~E-41 을 하나씩 시험으로 옮긴다. 명중 굴림이 걸린 시험은 굴림 값을 알고 있는 시드를 쓰거나, `hit_rolled` 의 `roll`·`need` 로 판정을 확인한다.
  2. **같은 시드 2회:** 같은 시드·같은 행동 목록 → 이벤트 JSON 해시 동일(E-35).
  3. **저장·재개 동일:** 중간 저장·불러오기 → 끊김 없는 실행과 동일(E-37).
  4. **미리보기 비소비:** 미리보기 전후 난수 상태 동일(E-34).
  5. **스트림 독립:** 한 스트림 사용이 다른 스트림 결과를 바꾸지 않음(E-36).
  6. **골든 재현:** 고정 시드·고정 행동 목록의 이벤트 해시를 저장소에 둔다. 규칙을 의도적으로 바꾸면 해시를 갱신하고 커밋 본문에 이유를 적는다. 의도하지 않은 해시 변화는 실패다.
  7. **엔진 난수 감시:** 지금의 감시 시험 유지.
- 하네스의 정답 시험은 이 저장소에 두지 않는다(AGENTS 47). 위 시험은 규칙 엔진의 일반 시험이다.

## 15. 열린 질문과 다른 문서 연동
