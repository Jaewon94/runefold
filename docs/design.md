# Runefold 설계 (초안 v0)

## 한 줄 요약
타일 위에서 소대를 움직이는 전술 전투 + 카드 기반 행동 + 합성 승급 + 유물 빌드의 판타지 로그라이크.

## 참고작과 반영 방식
| 축 | 참고작 | 룬폴드 |
|---|---|---|
| 전투 | XCOM·라피스 | 8×8 안팎 타일 격자, 유닛 3~4명, 한 턴에 이동 + 행동. 엄폐·고저차·사거리 모양, 적 행동 예고 |
| 행동 | 슬레이 더 스파이어 | 유닛별 직업 카드, 매 턴 손패 5장, 공유 에너지 3. 카드가 공격·방어·마법을 정함 |
| 합성 | 아르카나 택틱스 | 야영지에서 같은 유닛 3명 → ★ 승급(1→2→3). 같은 카드 2장 → 강화 카드(+) |
| 성장 | 슬레이 더 스파이어 | 층 지도(전투/엘리트/상점/이벤트/야영/보스), 보스·저주 유물, 태그 시너지(불꽃·방어·합성·소환) |
| 분위기 | 판타지 | 타로식 대비전(Arcana) 세계관. 보스는 타락한 아르카나 |

## 핵심 결정
- 이동은 유닛 스탯으로 공짜, 행동만 카드와 에너지로 제한한다(이동까지 카드로 하면 템포가 느려진다).
- 규칙 엔진은 렌더링과 분리한다. 순수 TypeScript, 시드 고정 난수, 결정론적 시뮬레이션.
  화면 없이 vitest 로 전투·합성·유물 규칙을 검증한다.

## 직업 (MVP 4종)
기사(방어·도발) · 레인저(원거리·위치) · 마법사(원소 조합) · 성직자(회복·정화). 추후 도적·소환사.

## 한 판
3막 × 약 12노드, 30~45분. 메타 성장은 직업·유물 해금과 난이도 단계.

## 목표 플랫폼
Steam 출시용 네이티브 PC 게임(Windows 우선, Steam Deck 고려). 웹 게임이 아니다.
Steamworks 연동(업적·클라우드 저장·Steam 입력)과 Steam 상점 요건(캡슐 이미지·트레일러)이 필요하다.

## 기술안 (엔진 미정 — 결정 대기)
- **Godot 4 (추천):** 무료·MIT, 씬/리소스가 텍스트라 git 과 에이전트 작업에 유리하고, 헤드리스 실행·CLI 내보내기가 된다.
  Steam 연동은 GodotSteam 으로 한다. 시험은 GUT 또는 GdUnit4. 언어는 GDScript(추가 설치 최소) 또는 C#(.NET SDK 필요).
- **Unity:** 자료가 많지만 에디터 의존이 크고 씬이 무거워 SSH 에이전트 작업에 불리하다.
- 어느 쪽이든 **규칙 엔진은 렌더링과 분리**한다(시드 고정 난수, 결정론적 시뮬레이션, 화면 없이 시험 가능).
- 아트·오디오는 임시 도형/무료 에셋으로 시작하고, 에셋은 받을 때 출처 URL·라이선스 확인일을 기록한다.
  이진 에셋이 늘면 git LFS 도입을 검토한다.
- 엔진 버전·설치 방법은 설치 시점에 공식 사이트에서 확인하고 URL 과 확인 날짜를 남긴다.
