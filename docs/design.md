## 용어 정의
문서에 적힌 뜻 그대로 옮겼다. 새 뜻을 만들지 않았고, 문서끼리 뜻이 다르거나 정의가 없으면 그렇게 표시했다.

| 용어 | 뜻 | 출처 |
|---|---|---|
| 소대 | 전투에서 움직이는 아군 전체. 소대가 하나의 덱·손패 5장·에너지 3을 공유한다(소대 공유 덱). 종이 프로토타입의 기본형은 아군 4명. 대기석 유닛이 소대에 들어가는지는 문서에 없음(미확인) | 이 문서 「한 줄 요약」·「M1 전 결정」; paper-prototype.md L17, L35 |
| 출전 | 격자에 나가 싸우는 유닛. 4명에서 시작해 최대 8명(상한 잠정) | 이 문서 「M1 전 결정」(정원) |
| 대기석 | 출전하지 않는 유닛을 두는 칸. 6칸(잠정, M3 실측). 한 판 안에서 합성 재료를 모으는 곳이다. **창고와는 별개** | 이 문서 「M1 전 결정」; difficulty-plan.md L45 |
| 창고 | 런 사이에 일부 캐릭터를 맡겨 다음 런으로 이월하는 칸(제안 단계). 야영지에서만 맡길 수 있고 맡긴 유닛은 그 런에서 싸우지 못한다 | difficulty-plan.md 6절(L37~L47) |
| 지휘관 | 주 지휘관 1 + 부지휘관으로 소대를 편성하는 방식(4인 시작, 최대 8인). 승급마다 직업이 한 단계 위로 바뀌는 「단 성장」과 함께 잠정. 주 지휘관이 쓰러지면 즉시 패배하는 규칙은 **변형 C 시험에만** 있다 | 이 문서 「방향」; paper-prototype.md L97 |

- **C5 지휘관의 위상:** 지휘관 편성은 확정(방향)(roadmap.md L275)이고 이 문서 「방향」에 있으나, 종이 프로토타입은 주 지휘관 사망 패배를 시험 변형 C 로만 둔다. 기본 패배 조건은 전멸(가정).
- **C6 「T」:** 변형 T(틱) ↔ 티어 T1~T7. 같은 글자가 다른 뜻이다.
- **C7 「막」:** 한 판의 구간(act) ↔ 방어막(paper-prototype.md L18, L40).
- **C8 「층」:** 이 문서는 「층 지도」, 다른 문서는 「막」·「노드」를 쓴다. 층과 막의 관계가 정의되지 않았다.
- **C10 이동 취소 범위:** 이 문서 「M1 전 결정」은 「유닛당 한 번, 행동 카드를 쓰기 전이면 취소」로 읽히고, paper-prototype.md L22 는 「어느 유닛이든 카드를 한 장 쓰면 그 전의 모든 이동이 확정」(소대 단위)이다. 종이 프로토타입은 후자로 시험한다.
- **C11 승급 규칙 확정 범위:** 「항상 3개→1개」는 ★1→★3 구간만 확정으로 본다. ★4 이상 재료 수는 job-tree-plan.md 10-2 곡선 가설(미정)이며 3개가 아닐 수 있다(C2). 직업 100개 이상·한 판 획득 수와 ★3 도달 확률의 관계는 RUNE-24 시뮬레이션 전까지 근거가 없다.
- **C9 직업 규모 표기:** README L45 「직업 4종」 ↔ 100개 이상(이 문서). roster-plan.md L77 에 따라 4종은 검증 세트 이후 기본 직업으로 들어가는 출발점이다(README 갱신 대기).

## 한 줄 요약
타일 위에서 소대를 움직이는 전술 전투 + 카드 기반 행동 + 합성 승급 + 유물 빌드의 판타지 로그라이크.

## 핵심 결정
- **설계의 최우선 기둥(사용자 2026-10-27): 직업(캐릭터 종류)이 매우 많고, 합성으로 생기는 직업도 매우 많고, 티어가 잘 나뉘어 있고, 캐릭터가 디자인적으로 매력적일 것.** 목표 규모는 직업 총 100개 이상, 티어는 **7단계(7성)까지**이다(사용자 2026-10-28, 처음 10티어 → 5~6 → 7로 조정). **높은 티어는 정말 만들기 어려워야 한다.** 의미와 만드는 방식은 미정이다. 직업의 소재는 **동서양·중세·현대·판타지·무협·선협·초능력·신화·전설·이야기·게임·괴담·추리 등 모든 이야기**에서 나올 수 있다(사용자 2026-10-27). **하드 로그라이크(사용자 2026-10-27): 획득은 랜덤이고 죽으면 정말 사라지는 어려운 게임**(런 중 쓰러진 유닛은 영구 소멸, 런 사이에 전력은 이월하지 않되 **창고에 맡긴 일부 캐릭터는 이월**(2026-10-28), 도감·직업 해금은 남음)([difficulty-plan.md](difficulty-plan.md)). **밸런스 원칙(사용자 2026-10-27): 근·중·원거리의 균형, 상위 티어는 더 세되 하위 티어도 어딘가에서 도움이 되게**(job-tree-plan.md 8절). 계획과 선택지는 [job-tree-plan.md](job-tree-plan.md), 로스터 초안(세계 14개, 약 122개 가칭)은 [roster-plan.md](roster-plan.md).
- 이동은 유닛 스탯으로 공짜, 행동만 카드와 에너지로 제한한다(이동까지 카드로 하면 템포가 느려진다).
- 규칙 엔진은 렌더링과 분리한다. 엔진 API 에 기대지 않는 순수 코드, 시드 고정 난수, 결정론적 시뮬레이션.
  화면 없이 규칙 엔진의 헤드리스 시험으로 전투·합성·유물 규칙을 검증한다. (여기서 "엔진 API"는 Godot 이고, "규칙 엔진"은 우리 규칙 코드다.)

## 참고 원칙 (사용자 2026-10-27)
참고작(XCOM, 슬레이 더 스파이어, 네오 다크세이버 등)은 **구조와 아이디어를 참고**하는 것이지 복제하는 것이 아니다.
- 차용하는 것: 규칙의 구조, 흐름, 시스템 조합, 느낌. 자기 규칙·수치·이름·텍스트·도트로 새로 만든다.
- 가져오지 않는 것: 상대 게임의 코드, 에셋, 이름, 문구, 화면 배치의 그대로 복제, 디컴파일·추출물.
- 이 저장소는 공개이므로 위 원칙을 어긴 자료를 올리지 않는다.

## M1 전 결정 (2026-10-21, 상태는 줄마다 표기)
- 격자: 8×8 고정, 고저차 없음. 장애물·엄폐 칸만 둔다.
- 턴: 팀 턴(아군 전원이 행동한 뒤 적 전원이 행동). 이동은 유닛당 한 번이며 행동 카드를 쓰기 전이면 취소할 수 있다(잠정).
- 명중: 확률(XCOM식). 화면에 표시한 확률은 항상 정확해야 한다. 사용자가 추천(확정 명중)과 다르게 선택했으며 종이 프로토타입에서 '빗나가서 억울함'을 우선 검증한다.
- 사망: 전투 중 쓰러진 유닛은 영구 손실. 패배 조건은 전멸로 가정(미확정). 쓰러진 유닛의 직업 카드 처리는 미정이며 종이에서는 「뽑는 즉시 버리고 1장 다시 뽑는다」를 임시로 쓴다. 합성으로 키운 유닛을 확률로 잃을 수 있어 완화 장치(부활·보호 카드 등)를 종이 프로토타입에서 시험한다.
- 덱: 소대 공유 덱 + 직업 태그. 손패 5장·에너지 3을 공유하고 카드를 낼 때 실행 유닛을 고른다(직업 카드는 해당 직업만).
- 정원(2026-10-22 사용자 결정): 출전 인원은 **4명에서 시작해 판이 진행되며 최대 8명까지 늘어난다**. 상한 8은 잠정이며 종이 프로토타입 변형 N(6명·8명)으로 격자 혼잡·턴 길이·에너지 병목을 보고 확정한다. 대기석 6칸(M3 실측으로 조정, 잠정). 출전 인원이 늘어나는 방식(어느 보상·단계에서 +1)은 미정.
- 스탯: 유닛은 HP·이동력·방어를 가진다. 공격력과 사거리는 카드가 정한다.
- 합성: 승급은 정리 화면에서 플레이어가 확정, 조합식은 서로 다른 재료 2~3개 → 새것(「합성과 등급」 참조).

## 방향: 네오 다크세이버 느낌 강화 (2026-10-21)
- 방향(사용자 결정): 네오 다크세이버(라피스) 느낌을 더 강하게 가져간다. 카드 행동, 로그라이크 구조, 합성·조합식, 유물은 유지한다.
- 틱 차용(일부만, 잠정): 팀 턴이 기본이다. 적 틱 카운터(몇 라운드 뒤 행동할지)와 강한 카드가 사용 유닛의 다음 이동을 늦추는 「지연」은 종이 프로토타입 변형 T 로 시험한 뒤 채택 여부를 정한다. 실시간 진행은 하지 않는다. (네오 다크세이버의 틱은 실시간 게이지이고, 적 카운터는 Wildfrost 의 구조에 가깝다.)
- 지휘관 편성(주 지휘관 1 + 부지휘관, 4인으로 시작해 최대 8인)과 단 성장(잠정): 승급(★2~★7)마다 한 단계 위의 직업으로 바뀌어 도트 외형이 새로 필요하고 직업 카드 1장이 덱에 추가되며 HP·방어가 오른다(잠정 제안). 외형 수는 직업 수와 같다(100개 이상). 무료 에셋 단계에서는 색조·장식 변화로 대체한다.
- 시나리오 진행 차용(해석, 잠정): 로그라이크 노드는 그대로 두고 각 막을 스토리 한 화로 연출한다(막 시작·끝과 보스 전 짧은 대화). 텍스트와 번역이 늘어난다.
- 도트 SRPG 분위기와 UI(잠정): 해상도 목업(RUNE-42)과 아트 방향에 반영한다.

## 합성과 등급
**합성은 두 갈래다.** (1) 승급: 같은 것 3개 → 1개(2개 승급은 없다). (2) 조합식: 서로 다른 재료 2~3개 → 새로운 하나(고정 레시피표).
- 대상은 유닛과 카드. 승급은 이름과 단계가 모두 같은 3개만 합쳐진다(다른 단계·다른 이름은 승급 재료로 섞이지 않는다).
- 단계는 **★1→★7**(사용자 2026-10-28: 7성까지, **★ = 티어 = 직업의 위계**). 승급하면 한 단계 위의 직업이 된다(이름·외형·스킬이 바뀜). ★2~★4 는 같은 직업 합성으로, ★5~★7 은 합성에 더해 특수 재료·조건이 필요하다. **높은 티어는 만들 수는 있되 시간을 많이 쏟거나 운이 좋아야 한다.** 재료 수 곡선은 [job-tree-plan.md](job-tree-plan.md) 10절 초안. 카드의 단계(Lv)는 별도 결정(미정).
- 합성 결과는 능력치·효과가 오르지만 **등급(희귀도)은 바뀌지 않는다.** 단계와 등급은 별개 축이다. 승급 보상은 「방향」 절의 정의(외형 변화 + 직업 카드 1장 + HP·방어 상승)를 따른다.
- 합성 시점은 야영지와 상점 전후의 정리 화면이다. '합성 가능'이 표시되면 플레이어가 직접 확정한다(자동 아님, 잠정, M4 시험).
- 조합식(2026-10-21 결정): 대상은 유닛과 카드(유물 제외). 서로 다른 재료 2~3개 → 새 이름의 하나이며 고정 레시피표로 관리한다. 일부 레시피는 처음부터 보이고 나머지는 발견하면 도감에 기록한다. 결과는 재료 단계와 무관하게 항상 ★1(Lv1)로 시작하고, 그 뒤 같은 이름 3개 승급은 기존 규칙을 따른다. 같은 것 3개를 모으기 어렵다는 위험의 두 번째 길이기도 하다.
- 유물은 합성하지 않는다.

**등급(희귀도) — 유닛·카드·유물 공통, 4단계**
| 등급 | 색 | 비고 |
|---|---|---|
| 일반 (Common) | 회색 | 가장 흔함, 합성 재료의 주류 |
| 고급 (Uncommon) | 초록 | |
| 희귀 (Rare) | 파랑 | 빌드 핵심 |
| 전설 (Legendary) | 주황 | 보스·특수 보상 위주, 한 판에 1개 안팎 |
유물은 이에 더해 보스 유물과 저주 유물 분류를 둔다. 등급별 출현 확률과 가격은 M3 에서 정한다.

**미결:** 티어(7단계)의 의미와 높은 티어를 어렵게 만드는 방식, 합성과의 관계(job-tree-plan.md 2절) · 전설 유닛 존재 여부 · 합성 단계별 능력치 증가폭 · 조합식 레시피 개수와 구성 · 대기석 6칸의 적정성(M3 실측).
**합성 빈도:** 3개 합성은 한 판 안에서 같은 것을 3개 모으기 어렵다. 풀을 작게 유지하고, 이미 가진 것이 나올 확률을 높이고, 상점에서 고르거나 살 수 있게 한다. M4 에서 실측한다.

## 직업
직업은 세계(장르) × 역할 × 티어의 세 축으로 만든다([roster-plan.md](roster-plan.md)). 최종 규모는 직업 100개 이상(기본 + 합성, 방향 확정, 개수는 계보 설계로 확정)이다. **게임성 검증 세트는 기본 6 + 합성 6**(확정)이며, 기본 6은 서로 다른 세계에서 하나씩 고른 기사 · 검객 · 마법사 · 퇴마사 · 탐정 · 용사이다([roster-plan.md](roster-plan.md) 5절, 2026-10-29 채택). 기존 MVP 4종(기사·레인저·마법사·성직자)은 검증 세트 이후 기본 직업으로 들어간다. 합성 직업 6개의 계보는 [job-tree-plan.md](job-tree-plan.md) 에서 정한다.

## 한 판
목표 30~45분(숙련자 기준, 처음 하는 사람은 더 길다. 전투 N분 × 전투 수 예산식은 M3 실측으로 정한다). 메타 성장은 직업·유물 해금과 난이도 단계.

## 아트 방향
**2D 도트(픽셀아트), 움직임은 최소.** 턴제라 큰 애니메이션이 필요 없고, 제작 비용과 에셋 수를 줄이는 방향이다.
- 기준 해상도 **640×360**(잠정, 2026-10-21 목업 결과), 정수 배율(×3 = 1080p, ×4 = 1440p, ×6 = 4K)로 확대한다. 타일은 **32×32**(잠정)이며
  무료 에셋 조사(RUNE-20)에서 32px 팩이 충분한지 확인한 뒤 확정한다. Steam Deck(1280×800)은 ×2 = 1280×720 으로 가로를 꽉 채우고 위아래에 여백이 남는다.
  근거와 한계는 docs/resolution-mockup.md.
- 유닛 스프라이트는 대기 2~4프레임이 기본이다. 공격·피격·이동은 별도 프레임 대신 위치 이동(트윈), 흰색 번쩍임,
  화면 흔들림, 간단한 파티클로 표현한다.
- **캐릭터·몬스터의 움직임은 최소로 한다.** 걷기·달리기 프레임은 만들지 않는다. 타일 이동은 대기 프레임 그대로 칸 사이를 미끄러지듯 옮기고,
  공격은 앞으로 살짝 내딛었다 돌아오는 트윈, 피격은 흰색 번쩍임과 밀림, 사망은 페이드아웃으로 처리한다. 직업·몬스터당 필요한 그림은 대기 2~4프레임이 전부다.
- 카드·유물은 정지 아이콘(예: 32×32)으로 제작한다. 일러스트 풀 컷은 쓰지 않는다.
- 검증 단계는 직업 6+6 규모로 무료 에셋·임시 도형을 쓴다. 최종 규모(직업 100개 이상)의 디자인 방식(도트 스프라이트, 포트레이트, 혼합)은 아트 방식 시험으로 정한다(job-tree-plan.md). AI 생성을 쓰면 Steam 콘텐츠 설문에 공개한다.
- 도구 후보는 Aseprite(유료)와 무료 대안(LibreSprite, Pixelorama). 가격·라이선스는 도입 시점에 URL 과 확인일을 남긴다.
- 에셋 라이선스는 받을 때 출처 URL·확인일을 기록한다.

## 목표 플랫폼
Steam 출시용 네이티브 PC 게임(Windows 우선, Steam Deck 고려). **(2026-10-27) 웹 게임 방향을 우선 검토 중이며 불가하면 이 방향을 유지한다**(결정 장부 DEC50 = 플랫폼 방향 결정, 대기 중, docs/platform-direction.md).
Steamworks 연동(업적·클라우드 저장·Steam 입력)과 Steam 상점 요건(캡슐 이미지·트레일러)이 필요하다.

## 기술안
- **엔진: Godot 4 확정**(2026-10-20 사용자 결정). 설치한 버전·출처·확인일은 [README](../README.md) 「개발 환경」에 기록한다.
- Steam 연동은 GodotSteam, 시험은 **GUT 9.7.1 로 확정**(CI 가 이미 사용 중), 언어는 GDScript(C# 은 .NET SDK 가 필요해 보류).
- 규칙 엔진과 렌더링의 분리 원칙은 「핵심 결정」을 따른다.
- 아트는 2D 도트(위 「아트 방향」). 개발 초기에는 임시 도형으로 시작한다.

## 비목표와 위험 (EGM 검토 반영, 2026-10-29)

- 비목표: 실시간 진행, 유물 합성, 웹 게임으로의 확정(미결).
- 설계 수준 위험(책임 문서가 없던 것): ① 직업 100개 이상 대 한 판의 합성 빈도, ② G3 에서 합성이 삭제되면 직업 수(조합식 24개 포함 약 122개, 빼면 98개)와 티어 기둥이 함께 흔들린다, ③ 한 판 30~45분 대 전투 길이(paper-prototype.md 는 전투 15~25분 목표)와 노드 수, ④ 승급 시 직업 카드 처리와 보유 한도(출전 8 + 대기석 6 초과 시) 규칙 부재, ⑤ GodotSteam 은 웹에서 쓸 수 없다(platform-direction.md). 위험 표 정본은 roadmap.md 8절이며 ①~④는 아직 거기 없다. 정리 담당 이슈 미생성(미확인).
