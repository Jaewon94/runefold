# EGM 시험 계획 (사전 등록, 2026-10-27)

Google Elephant-Goldfish Model(EGM, https://github.com/google/elephant-goldfish-model, Apache-2.0, 확인 커밋 3d0b348)은 AI 모델이 아니라
설계 우선 개발 플러그인이다. 깊은 맥락의 Elephant 세션이 설계 문서를 쓰고, **맥락이 없는 Goldfish 서브에이전트**가 그 문서만 읽고 검토한다.
도집사 쪽 결정은 "다른 서비스를 만들 때 작게 시험"이었고 사용자가 Runefold 에서 쓰라고 했다(2026-10-27).

**이 문서는 결과를 보기 전에 채택 기준을 고정하기 위한 것이다.** 결과는 NOT RUN 이다. 시험 뒤에 기준을 바꾸지 않는다.

## 1. 시험 대상과 방법
- 대상: `docs/design.md`(시험 시작 시점의 main 커밋을 결과 문서에 기록).
- 방법: EGM 의 `/egm-review` 파이프라인(Zoom Out → Comprehension → Critic → Readiness → Synthesizer)을 **같은 에이전트 정의**(클론의 `agents/*.md`)로 실행한다.
  이 세션에서는 플러그인을 직접 로드할 수 없으므로 정의를 서브에이전트 지시로 사용한다(플러그인 실행이 아님을 결과에 명시).
- 각 서브에이전트는 **대상 문서와 필요한 저장소 문서만** 읽고, 이 세션의 결론·이전 검토 결과를 보지 못한다(맥락 없음, Goldfish).
- 모델: Sonnet 5.5(사용자 2026-10-26 지시: Fable 금지, 최고 Opus). 단계별 토큰 사용량을 기록한다.

## 2. 대조군
- 이전 독립 검토 A(2026-10-21, 같은 문서의 이전 판, 설계 일관성). 지적 목록은 결정 장부와 로드맵 14절에 요약돼 있다.
- 비교: EGM 지적을 대조군 지적과 대응시켜 **중복 / 새로 발견 / 틀림**으로 분류한다. 문서가 그 사이 바뀌었으므로 대조군이 이미 해결된 항목은 "해결됨"으로 따로 센다.

## 3. 채택 기준 (시험 전 고정)
다음을 **모두** 만족하면 이후 큰 설계 문서에 EGM 검토를 정기적으로 쓴다. 하나라도 못 미치면 쓰지 않는다.
1. **새로 발견한 유효 지적 5개 이상.** 유효 = 문서 본문이나 공식 자료로 사람이 직접 확인되는 지적.
2. **오탐률 30% 이하.** 확인했더니 틀린 지적의 비율.
3. **비용 상한:** 전체 서브에이전트 토큰 합계 60만 이하.
   - **집계 정의 보충(사용자 2026-10-29):** 기준 3 의 토큰은 입력+출력+추론+캐시 쓰기의 합이며 **캐시 읽기는 제외**하고 달러 비용을 병기한다. 이 정의는 **다음 시험부터** 적용한다. 1·2차 시험에는 소급하지 않는다(2차는 두 집계를 모두 기록하고 판정을 보류했다, [egm-trial-2-result.md](egm-trial-2-result.md)).
4. **누설 없음:** 서브에이전트가 이 세션의 결론이나 이전 검토 결과를 보지 않았음이 프롬프트로 확인됨.
5. 판정자는 이 세션이며 확인 방법(어느 줄·어느 문서로 확인)을 지적마다 적는다. 확인하지 못한 것은 "미확인"이며 유효로 세지 않는다.

## 4. 기록할 것
지적 목록(단계별), 분류(중복/신규/오탐/해결됨), 토큰 사용량, 사용한 에이전트 정의 파일, 판정, 소요 시간.
Jira 는 RUNE-79. 결과 문서는 `docs/egm-trial-result.md`(시험 후 작성).

## 5. 한계
- 같은 계열 모델이 같은 계열 모델을 검토하므로 독립성이 낮다(도집사 쪽 평가와 같은 한계).
- 플러그인을 직접 실행하지 않고 정의를 빌려 쓰므로 EGM 전체(브레인스토밍·초안 단계)는 시험하지 않는다. 검토 단계만 본다.
- EGM 은 `docs/designs/` 를 설계 정본으로 삼지만 Runefold 의 정본은 Confluence 다. 이 시험은 검토 단계만 쓰므로 정본 충돌은 생기지 않는다.
