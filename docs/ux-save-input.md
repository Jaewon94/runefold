# UX·저장·입력 설계 (초안 v0.1, 2026-10-29)

RUNE-46(저장 시점·되돌리기 범위), RUNE-47(UX 최소 요구), RUNE-48(입력 추상화)을 한 문서에 묶는다.  
코드가 아니라 설계 문서다. M1 UI 구현 시 이 문서를 보고 작업한다.  
근거 문서: [design.md](design.md), [rules-engine-spec.md](rules-engine-spec.md), [difficulty-plan.md](difficulty-plan.md), [roadmap.md](roadmap.md), `AGENTS.md`.

상태 표기: **확정** = 사용자가 정했다 / **잠정** = 시험·실측 뒤 확정한다 / **미정** = 아직 정하지 않았다 / **미결** = 열린 질문으로 남김

## 1부: 저장 시점·되돌리기 범위 (RUNE-46)

하드코어 로그라이크에서 세이브 스컴을 원천 차단하는 저장 정책을 정한다.  
규칙 엔진 저장 계약(rules-engine-spec.md 12절)과 짝을 이룬다.

### 1-1. 저장 방식 **확정**

| 항목 | 결정 |
|---|---|
| 저장 방식 | 자동 저장만. 수동 저장 없음, 수동 되돌리기 없음 |
| 목적 | 세이브 스컴(저장→시도→불리하면 재로드) 원천 차단 |

슬레이 더 스파이어와 같은 구조다. 수동 저장 UI를 노출하지 않는다.

### 1-2. 자동 저장 시점 **확정**

아래 4개 시점에 런 파일(`run.json`)을 덮어쓴다.

| 시점 | 세부 |
|---|---|
| ① 노드 진입 시 | 지도에서 노드를 선택하고 화면이 전환될 때 |
| ② 전투 종료 시 | 승리·패배 판정 직후, 보상 화면 진입 전 |
| ③ 합성·보상 선택 확정 시 | 정리 화면에서 플레이어가 확정 버튼을 누른 직후 |
| ④ 야영지 출발 시 | 야영지 행동을 마치고 다음 노드로 이동할 때 |

근거: rules-engine-spec.md 12절 "전투 중 저장 = 전투 시작 스냅숏 + 행동 목록" 방식과 맞춘다. 전투 중에는 스냅숏이 남으므로 ②가 명시적 커밋 시점이 된다.

### 1-3. 세이브 파일 구조 **확정**

| 파일 | 내용 | 수명 |
|---|---|---|
| `run.json` | 현재 런 상태(분대·덱·지도·전투 스냅숏+행동 기록) | 런이 끝나면(승리·패배) 삭제 |
| `meta.json` | 도감·직업 해금·창고·통계 | 런을 넘어 영구 보존 |

세부 스키마는 rules-engine-spec.md 12절 참조. 파일 경로(OS별 저장 디렉터리)는 RUNE-15에서 결정한다. **미결**

### 1-4. 비정상 종료 복구 **확정**

| 상황 | 복구 방식 |
|---|---|
| 일반 플레이 중 종료 | 마지막 자동 저장 지점에서 재개 |
| 전투 중 종료 | 전투 시작 스냅숏에서 행동 목록을 재적용해 재개(rules-engine-spec.md 12절) |
| `rules_version` 불일치 | 그 전투를 처음부터 다시 시작, 진행 손실 알림 |

### 1-5. 시드 공유·일일 도전 **잠정**

- 창고(보관) 비활성화: 창고 유닛은 시드 밖의 입력이므로 시드 공유·일일 도전 모드에서는 창고를 끈다(difficulty-plan.md 3절 경고).  
- 시작 조건(직업·덱·분대)은 시드에 포함해 고정한다.  
- 구체 UI와 모드 전환 방식은 **미정**. M5 이후 확정한다.

### 1-6. 되돌리기 범위 **확정**

| 행동 | 취소 가능 여부 | 근거 |
|---|---|---|
| 유닛 이동 | 가능. 행동 카드를 한 장도 쓰지 않은 상태에서만 | design.md L129, rules-engine-spec.md 3절 |
| 카드 사용 | 불가. 카드 사용 즉시 `moves_locked` 상태로 진입 | rules-engine-spec.md 3절 E-04 |
| 합성·보상 선택 확정 | 불가. 확정 버튼 이후 자동 저장됨 | 1-2절 ③ |

되돌리기는 난수를 쓰지 않는 행동(이동·취소)만 허용한다. 굴림 뒤 되돌리기는 "미래 엿보기"가 되므로 금지한다(rules-engine-spec.md 11절).

취소 행동: `cancel_move(unit_id)`. 카드 1장이라도 사용하면 `moves_locked`가 되고 이후 `cancel_move`는 `action_rejected{moves_locked}`로 거부된다.

### 1-7. 미결

| 항목 | 담당 이슈 |
|---|---|
| 저장 파일 경로(OS별 디렉터리) | RUNE-15 |
| 저장 압축 방식(JSON 평문 vs gzip) | 미정 |
| 세이브 마이그레이션 시험 | roadmap.md M5.9 |

## 2부: UX 최소 요구 (RUNE-47)

M1 시작 전에 반드시 구현해야 할 UX 세 가지를 정한다.  
참고: Floppy Knights 사용자 불만 대부분이 UX 부재였다(RUNE-47 이슈 배경).

### 2-1. 사거리 미리보기 **확정** (M1 완료 기준)

유닛을 선택하면 즉시 오버레이를 표시한다.

| 오버레이 | 색 | 조건 |
|---|---|---|
| 이동 가능 칸 | 파랑 | 이동력 이하, 경로 존재, 장애물·유닛 없음 |
| 공격 가능 칸(선택한 카드 기준) | 빨강 | 카드 사거리(맨해튼 거리) 이하 |

- 이동 후 공격 가능 칸도 미리 표시해야 한다(이동 목표 칸을 hover/포커스할 때 갱신).  
- `Rules.preview`를 사용하며 난수를 소비하지 않는다(rules-engine-spec.md 11절 "미리보기는 난수를 쓰지 않는다").  
- 상태이상(이동력 감소 등)이 있으면 실제 이동 범위에 반영한다.

### 2-2. 적 턴 건너뛰기 **확정** (M1 완료 기준)

적 행동 애니메이션을 빠르게 재생하는 토글이다.

| 상태 | 동작 |
|---|---|
| 기본 속도 | 적 이동·공격 애니메이션 정상 재생 |
| 빠른 속도 | 애니메이션 속도 ×N 배 (배수는 **잠정**, 시험 후 조정) |

- 버튼 위치: 화면 우하단 또는 적 턴 중 접근 가능한 고정 영역. 정확한 위치는 **미정**.  
- 빠른 속도 중에도 `intent_set`·`unit_downed` 이벤트는 모두 처리한 뒤 결과를 표시한다. 규칙 결과가 달라지지 않는다.  
- 설정에서 기본값 지정 가능. M5 이후 설정 화면과 통합한다.

### 2-3. 이동 취소 **확정** (M1 완료 기준)

행동 카드를 사용하기 전이면 이동을 취소할 수 있다(1부 1-6절과 연동).

| 방법 | 설명 |
|---|---|
| UI 취소 버튼 | 이동한 유닛이 선택된 상태에서 노출되는 "취소" 버튼 |
| 우클릭 | 마우스 오른쪽 버튼으로 현재 유닛 이동 취소 |
| 패드 B 버튼 | 3부 2-3절 참조 |

- 취소 가능 상태(`moves_locked == false`, 해당 유닛이 이미 이동했음)일 때만 UI를 노출한다.  
- 취소 후 유닛은 원래 칸으로 돌아가고 이동력이 복원된다(`cancel_move` 이벤트).  
- 카드를 한 장이라도 사용하면 취소 버튼을 숨긴다(`moves_locked` 진입).

### 2-4. M2 이후 추가 UX (우선순위 낮음)

| 기능 | 설명 | 시기 |
|---|---|---|
| 카드 호버 확대 | 마우스가 카드 위에 있을 때 카드를 크게 표시하고 효과 설명 노출 | M2 |
| 상태이상 툴팁 | 유닛의 상태이상 아이콘을 hover·포커스하면 설명 표시 | M2 |
| 적 행동 의도 표시 | 적 턴 시작 시 각 적이 무엇을 할지 아이콘·숫자로 미리 표시 | M1 완료 기준에 이미 포함(rules-engine-spec.md 8절 `intents`), UI 세부는 M2 |

## 3부: 입력 추상화 (RUNE-48)

마우스·키보드·패드가 동일한 게임 액션을 수행하도록 Godot InputMap으로 추상화한다.  
Steam Deck 기준 점검(RUNE-28): 패드만으로 모든 콘텐츠 완주가 M5 목표다.

### 3-1. 액션 목록 **확정**

| 액션 이름 | 설명 |
|---|---|
| `action_select_unit` | 유닛 선택 / 재선택 |
| `action_select_move_target` | 이동 목표 칸 선택 |
| `action_select_card` | 손패에서 카드 선택 |
| `action_select_card_target` | 카드 대상(칸 또는 유닛) 선택 |
| `action_cancel` | 이동 취소 / 선택 해제 / 메뉴 닫기 |
| `action_fast_forward` | 적 턴 빠른 진행 토글 |
| `action_open_settings` | 설정 화면 열기 / 닫기 |

### 3-2. 기기별 기본 매핑 **잠정**

#### 마우스

| 입력 | 액션 |
|---|---|
| 좌클릭 | 유닛 선택 / 이동 목표 / 카드 선택 / 카드 대상 |
| 우클릭 | 취소 (`action_cancel`) |
| 휠 | UI 스크롤 (카드 목록 등) |

#### 키보드

| 키 | 액션 |
|---|---|
| `Tab` | 유닛 순환 선택 (`action_select_unit`) |
| 방향키 `↑↓←→` | 커서 이동 (격자 또는 카드 목록 탐색) |
| `Space` / `Enter` | 확인 (현재 커서 위치 선택) |
| `Esc` | 취소 (`action_cancel`) |
| `F` | 빠른 진행 토글 (`action_fast_forward`) |
| `P` | 설정 열기 (`action_open_settings`) |

#### 패드 (Steam Deck 기준)

| 버튼 | 액션 |
|---|---|
| 왼쪽 스틱 / 방향패드 | 커서 이동 (`action_select_move_target` 이동) |
| A | 확인 (`action_select_unit` / `action_select_card_target`) |
| B | 취소 (`action_cancel`) |
| RB (오른쪽 범퍼) | 유닛 순환 (`action_select_unit`) |
| Y | 빠른 진행 토글 (`action_fast_forward`) |
| Start / Menu | 설정 열기 (`action_open_settings`) |

### 3-3. 구현 원칙 **확정**

1. **Godot InputMap으로 추상화**: 모든 게임 로직은 `Input.is_action_pressed("action_*")` / `Input.is_action_just_pressed("action_*")` 형태로만 입력을 받는다. 기기별 키를 하드코딩하지 않는다.

2. **하드코딩 금지**: 코드에 `KEY_SPACE`, `JOY_BUTTON_0` 같은 상수를 직접 쓰지 않는다. 반드시 InputMap 액션 이름을 거친다.

3. **리매핑 지원(M5 이후)**: 설정 화면에서 각 액션의 키·버튼을 바꿀 수 있게 한다. M1~M4는 기본 매핑 고정으로 시작하고 M5에서 리매핑 UI를 추가한다.

4. **Steam Deck 완주 점검(RUNE-28)**: M5 이전이라도 패드 매핑이 모든 게임 흐름(전투·합성·지도·설정)을 커버하는지 수동 점검한다.

5. **규칙 엔진과 입력 분리**: InputMap 처리는 `godot/ui/` 아래에서만 한다. 규칙 엔진(`godot/game/`)은 입력 API를 부르지 않는다(rules-engine-spec.md 2-1절, 13절).

### 3-4. 미결

| 항목 | 내용 |
|---|---|
| 커서 이동 속도(패드 스틱) | 스틱 감도·반복 입력 간격 조정값. M1 시험 후 확정 |
| 카드 선택 방식(패드) | 카드가 여러 장일 때 LB/RB로 순환할지, 스틱 좌우로 탐색할지 **미정** |
| 리매핑 저장 위치 | `meta.json` 에 포함할지 별도 설정 파일로 분리할지 **미정** |
| Steam Input API 연동 | GodotSteam M5b 이후. 그 전까지는 Godot InputMap으로만 처리 |
