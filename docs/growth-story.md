# 단 성장 설계 · 막 스토리 연출 범위 (RUNE-72 · RUNE-73)

상태 표기: **확정** = 사용자가 정했다 / **잠정** = 시험·실측 뒤 확정한다 / **미정** = 아직 정하지 않았다 / **제안** = 이 문서가 정한 값(근거 요지 함께 적음)

---

## 1부: 단 성장 설계 (RUNE-72)

승급(★1→★7)마다 유닛이 어떻게 변하는가를 정의한다. 승급 규칙의 근거는 [design.md](design.md) 「합성과 등급」, [job-tree-plan.md](job-tree-plan.md) 10-1·11절이다.

### 1. 외형 변화

| ★ 단계 | 외형 변화 | 상태 |
|---|---|---|
| ★1 | 기본형. 직업의 원형 실루엣·색조 | 확정(방향) |
| ★2 | 장비·색조 변화. 같은 실루엣에 소품·팔레트 추가 | 잠정 |
| ★3 | 눈에 띄는 변화. 장식 레이어 추가, 색 악센트 강화 | 잠정 |
| ★4 | 실루엣이 달라질 정도의 변화 | 잠정 |
| ★5 | 실루엣·색 모두 ★1과 확연히 다른 형태 | 잠정 |
| ★6 | 상위 직업 고유 외형, 특수 장식 | 잠정 |
| ★7 | 최상위 직업 외형. 격자에서 한눈에 구별됨 | 잠정 |

**확정(방향):** 승급하면 직업 이름과 외형이 바뀐다([job-tree-plan.md](job-tree-plan.md) 10-1).  
**확정(규칙):** 외형 수 = 직업 수. 각 직업의 ★ 단계마다 독립 스프라이트가 필요하다.

#### 솔로 개발 현실: C+B 혼합 방식 ([art-method-comparison.md](art-method-comparison.md) 3절 권고)

격자 위 스프라이트는 **모듈식(C)** — 머리·몸·팔레트 레이어 조합 — 으로 제작하고,
카드·UI의 **포트레이트(B)** 로 직업의 개성과 매력을 전달한다.

| 방식 | 쓰는 곳 | 이유 |
|---|---|---|
| C. 모듈식 | 격자 위 32px 스프라이트 | ★1~★3: 모듈식 레이어 조합 (팔레트·장식·무기 교체로 절감 가능). ★4~★7: 실루엣 변화 → 새 스프라이트 세트 필요. 계보 수를 제한해 부담 줄이기 (예: T5 이상 직업 12개만 고유 상위 외형) |
| B. 포트레이트 | 카드·UI | 32px 스프라이트의 표현 한계를 정지 일러스트로 보완. 직업의 매력 전달 |

AI 보조(D)는 포트레이트 초안에 한정해 부분 활용을 검토하되, Steam 콘텐츠 설문 공개 의무와
스타일 일관성 위험을 RUNE-84 시험에서 확인한 뒤에만 도입한다.

> 주의: 여기서 "직업 수"는 ★1 계보 기본 직업 수(T1 42개 + 크로스오버 24개 = 66개)가 아니라 모든 티어의 독립 직업 수(T1~T7 합계 약 122개) 기준이다. 계보가 수렴한다면 실제 고유 스프라이트는 122개 이하일 수 있다.

**솔로 개발 제약:** 직업 100개 이상 × ★7 = 최대 700개 스프라이트 세트.
검증 세트(기본 6 + 합성 6)부터 시작하고 최종 규모는 M5a 콘텐츠 예산 확정 후 결정한다.

---

### 2. 직업 이름·정체성 변화

승급할 때마다 직업명과 역할 정체성이 바뀐다.
**확정:** ★1~★7 = 직업의 티어(위계). 승급하면 한 단계 위의 직업이 된다([job-tree-plan.md](job-tree-plan.md) 10-1).

계보 예시 — 서양 중세 세계([roster-plan.md](roster-plan.md) 3절):

| ★ | 예시 계보 | 상태 |
|---|---|---|
| ★1 | 기사 | 채택(검증 세트) |
| ★2~★3 | (승급 계보 미정) | 미정 |
| ★4 | 근위기사 ← 계보 후보 중 하나 | 잠정 |
| ★5~★7 | (승급 계보 미정) | 미정 |

**미정:** 구체적 계보(어느 ★1이 어느 ★2로 이어지는지). G0 이후 설계.  
크로스오버 직업(조합식, 결과 ★1)은 같은 방식으로 계보를 이어가되, 어느 계보로 가는지는 열려 있다([job-tree-plan.md](job-tree-plan.md) 13-3).

---

### 3. 카드 추가

**잠정:** ★2~★7 승급마다 해당 직업의 고유 카드 1장이 덱에 추가된다. 추가되는 카드는 해당 상위 직업의 특기 카드이다.

| 시점 | 변화 | 상태 |
|---|---|---|
| ★1 시작 | 기본 카드만 덱에 있음 | — |
| ★2 승급 | 상위 직업 고유 카드 1장 추가 | 잠정 |
| ★3~★7 승급 | 각 상위 직업 고유 카드 1장씩 추가 | 잠정 |

**미정:** 쓰러진 유닛의 직업 카드 처리 방식([design.md](design.md) 「M1 전 결정」).  
**미정:** 카드의 Lv 승급은 유닛 ★과 별개로 둘지([job-tree-plan.md](job-tree-plan.md) 10-4 1번).  
**미정:** 승급 시 추가 카드 보유 한도(출전 8 + 대기석 6 초과 시 처리 규칙).

---

### 4. 능력치 상승

**잠정:** 승급할 때마다 HP와 방어가 오른다. 구체적 수치는 미정이며 M1 밸런스 설계에서 결정한다.

| 스탯 | 방향 | 상태 |
|---|---|---|
| HP | 승급마다 상승 | 잠정(수치 미정) |
| 방어 | 승급마다 상승 | 잠정(수치 미정) |
| 이동력 | 승급에 따른 변화 | 미정 |

공격력과 사거리는 카드가 정하므로 유닛 스탯 변화 항목이 아니다([design.md](design.md) 「M1 전 결정」).

---

### 5. 승급 방식 요약 (★별 변화 일람)

| 항목 | ★1→★3 | ★3→★7 |
|---|---|---|
| **승급 방식** | 같은 직업 ×3 → 1 (승급) | ×1 + 각성 재료·조건 (각성) |
| **외형** | 팔레트·장식 레이어 변화 | 실루엣까지 달라짐 |
| **직업명** | 바뀜 | 바뀜 |
| **카드 추가** | 고유 카드 1장 (잠정) | 고유 카드 1장 (잠정) |
| **능력치** | HP·방어 상승 (수치 미정) | HP·방어 상승 (수치 미정) |
| **재료** | 같은 직업 ★ ×3 | 유닛 ×1 + 각성 재료 |

각성 재료 제안([job-tree-plan.md](job-tree-plan.md) 11-4, 가칭, 수치는 RUNE-24 시뮬레이션 전 가설):

| 각성 | 재료 | 시간 경로 / 운 경로 |
|---|---|---|
| ★3→★4 | 룬 조각 2개 | 1막 엘리트 확정 1 + 상점 구매 / 이벤트 |
| ★4→★5 | 각성석 1개, 조건: 그 런을 ★4로 시작 | 2막 보스 확정 / 엘리트마다 10% |
| ★5→★6 | 각성석 2개 (한 런 안에서) | 2막·3막 보스 확정 각 1 / 엘리트마다 10% |
| ★6→★7 | 원형의 인장 1개 | 3막 보스 격파 50% / 희귀 이벤트 런당 2% |

- ★4 이상 각성은 **한 판에 한 단계까지**. ★5 이상은 판을 넘어야 한다.
- 창고([difficulty-plan.md](difficulty-plan.md) 6절)를 통해 높은 티어 유닛을 여러 판에 걸쳐 키울 수 있다.

**적용 대상:** 유닛만. 카드의 Lv 승급은 별도 결정(미정).

---

### 6. 미결 사항

| 번호 | 항목 | 상태 |
|---|---|---|
| 1 | 구체적 계보(★1→★2→…→★7 경로) | 미정. G0 이후 설계 |
| 2 | 승급 시 추가 카드의 보유 한도 초과 처리 | 미정 |
| 3 | 카드의 Lv 승급이 유닛 ★과 별개인지 | 미정(job-tree-plan.md 10-4 1번) |
| 4 | 쓰러진 유닛의 직업 카드 처리 | 미정(종이에서 임시 규칙 사용 중) |
| 5 | 각성 재료의 정식 이름·수치 | 미정. RUNE-24 시뮬레이션 전 가설 |
| 6 | 아트 방식 확정(C+B 혼합 검증 결과) | RUNE-84 시험 후 결정 |
| 7 | 최종 직업·스프라이트 규모 | M5a 콘텐츠 예산 확정 후 결정 |

- design.md 「합성과 등급」의 ★2~★4 합성 문구 변경 승인 필요 (곡선 Z 채택 전제, job-tree-plan 11-4 참조)
- 창고에서 꺼낼 때 ★ 하락 없음 가정 확인 (difficulty-plan 6절 vs job-tree-plan 11-4)

## 2부: 막 단위 스토리 연출 범위 (RUNE-73)

로그라이크 각 막의 시작·보스 전·클리어 시점에 짧은 스토리 연출을 삽입한다.
세계관 「접힌 이야기」([roster-plan.md](roster-plan.md) 1절)를 텍스트로 전달하는 최소 연출 설계이다.

---

### 1. 연출 시점

| 시점 | 내용 | 회수 |
|---|---|---|
| ① 막 시작 | 어디에 왔는가. 이 막의 배경·위험 제시 | 막마다 1회 |
| ② 막 보스 전 | 누구를 만나는가. 보스 소개·긴장 조성 | 막마다 1회 |
| ③ 막 클리어 | 무슨 일이 일어났는가. 다음 막 복선·결과 | 막마다 1회 |

막당 3회 × 3막 = **총 9회** 대화.

---

### 2. 연출 방식

**잠정:** 텍스트 대화창 형식.

- 화면 하단 또는 오버레이에 캐릭터 포트레이트 + 대사 2~4줄 표시
- 풀 보이스 없음 (텍스트만)
- 스킵 가능 (버튼 1회 또는 길게 누르기)
- 애니메이션 최소 (포트레이트 페이드인, 텍스트 타이핑 효과 정도)

**미정:** 포트레이트 존재 여부 — 아트 방식 확정(RUNE-84) 후 결정한다.
포트레이트가 없으면 직업 아이콘·이름 텍스트로 대체한다.

---

### 3. 분량 목표

| 항목 | 수치 | 상태 |
|---|---|---|
| 막당 대화 수 | 3회 | 잠정 |
| 총 대화 수 | 9회 (3막 × 3회) | 잠정 |
| 대화당 최대 줄 수 | 4줄 × 2캐릭터 = 최대 8줄 | 잠정 |
| 총 최대 대사 줄 수 | 72줄 (9회 × 8줄) | 잠정 |

---

### 4. 등장 캐릭터

| 캐릭터 | 역할 |
|---|---|
| 주 지휘관 | 매 대화에 등장. 소대를 이끄는 플레이어 캐릭터 |
| 막 NPC (막마다 1~2명) | 악당·협력자. 막마다 다른 캐릭터 등장 |

세계관 「접힌 이야기」 반영:
- 서로 다른 이야기 세계의 원형들이 한 곳에 겹쳐 있으므로 각 막의 NPC는 서로 다른 세계(Realm)에서 온 인물로 설정할 수 있다.
- 보스는 「타락한 원형」으로, 막 보스 전 대화에서 정체를 드러낸다([roster-plan.md](roster-plan.md) 1절).
- 구체적 캐릭터 이름·설정·대화는 스크립트 작성 단계에서 확정한다(미정).

---

### 5. 텍스트 동결과 번역

| 항목 | 내용 | 상태 |
|---|---|---|
| 텍스트 동결 시점 | RUNE-58 (M5.9 끝). 밸런스 변경이 카드 텍스트에 영향을 주므로 스토리 텍스트도 늦게 동결 | 확정(계획) |
| 원본 언어 | 한국어 | 확정 |
| 번역 대상 | 영어 (출시 전) | 확정(방향) |
| 번역 비용 | 콘텐츠 예산에 포함 (RUNE-44 갱신) | 잠정 |

---

### 6. 미결 사항

| 번호 | 항목 | 상태 |
|---|---|---|
| 1 | 대화 스크립트 작성 시점 | 미정 (M5a 콘텐츠 작업 시작 시점과 연동) |
| 2 | 포트레이트 존재 여부 | 미정. RUNE-84 아트 방식 결정 후 |
| 3 | 대화창 UI 사양 (위치, 폰트, 타이핑 속도) | 미정. RUNE-42 해상도 목업 연계 |
| 4 | NPC 캐릭터 목록·이름·설정 | 미정. 스크립트 작성 단계에서 확정 |
| 5 | 스킵 방식·조작 사양 | 미정. UI 구현 시점에 결정 |
| 6 | 대화 연출 중 게임 일시정지 여부 | 미정 |
