# 해금 시스템 설계 (RUNE-54)

## 1. 원칙

하드코어 로그라이크에서 메타 진행은 최소화하되 "다시 플레이할 이유"는 줘야 한다.

- **전력은 이월 없음**: 스탯, 카드 등 런 내 성장은 런이 끝나면 초기화된다.
- **해금 = 선택지 확장**: 해금은 강함을 이월하지 않고, 플레이어가 고를 수 있는 폭만 넓힌다.
  - 근거: `docs/difficulty-plan.md` 4절 "메타 진행 설계 원칙" 기준.

## 2. 해금 단위: 직업 계보

해금의 기본 단위는 **직업 계보 1개**다.

- 계보 구성: 기본 직업 1개 + 해당 직업에서 승급하는 모든 상위 직업.
  - 예: "전사 계보" = 전사(Lv1) → 용사(Lv2) → 영웅(Lv3).
- **시작 해금**: 종이 프로토타입 검증 세트 기본 6계보를 처음부터 해금 상태로 제공한다.
  - 이유: 첫 런부터 선택지가 너무 좁으면 게임을 경험하기 어렵다.

## 3. 해금 조건: 과제형

해금은 런 내 특정 과제를 달성하면 발생한다. 누적 플레이 시간이나 런 횟수 기반 조건은 쓰지 않는다.

| 조건 예시 | 해금 결과 |
|---|---|
| X 직업을 처음으로 파티에 편입 | Y 계보 해금 |
| 2막 보스 첫 격파 | 새 계보 1개 해금 |
| 특정 유물을 처음 획득 | 관련 계보 또는 유물 도감 등록 |

- 과제는 런이 끝난 시점에 판정한다(런 중에 팝업을 띄우지 않는다).
- 정확한 해금 조건 40개는 M5a 전에 확정한다 (→ 7절 미결 항목).

## 4. 해금 저장: meta.json

해금 정보는 런 파일과 **분리**해 저장한다.

| 파일 | 역할 |
|---|---|
| `run.json` | 진행 중인 런 상태 (런 종료 시 삭제 또는 초기화) |
| `meta.json` | 해금 목록, 도감 기록 (런이 끝나도 유지) |

- `meta.json` 예시 구조:
  ```json
  {
    "unlockedLineages": ["warrior", "mage", "archer"],
    "discoveredRelics": ["boots_of_speed", "iron_shield"],
    "unlockedRelics": ["boots_of_speed"]
  }
  ```
- 저장 위치와 직렬화 형식은 `docs/ux-save-input.md` 3절(저장 설계)과 연동한다.

## 5. 해금 화면 흐름

```
런 종료 (승리 또는 패배)
  └─ 조건 판정
       ├─ 신규 해금 있음 → "새 직업 계보 해금!" 팝업 표시 → 메인 메뉴
       └─ 신규 해금 없음 → 결과 화면 → 메인 메뉴
```

- 팝업: 계보 이름 + 기본 직업 아이콘 + "도감에서 확인하기" 버튼.
- **도감 화면**: 메인 메뉴에서 언제든 접근 가능. 전체 계보와 유물 목록을 잠금/해금 상태로 표시.
  - 미해금 항목은 실루엣으로 표시하고 "???" 이름을 보여준다.

## 6. 유물 해금

유물도 같은 방식으로 해금된다.

- **도감 등록**: 런 중 처음 획득한 유물은 런 종료 후 `meta.json`의 `discoveredRelics`에 기록된다.
- **상점 등장**: 도감에 기록된 유물은 다음 런부터 상점 풀에 추가된다.
  - 이유: 처음 보는 유물이 상점에 나와도 플레이어가 효과를 알 수 없으므로, 한 번 발견 후 구매 선택이 가능하게 한다.
- **해금과 등록의 차이**:
  - 등록(discovered): 도감에 기록됨, 효과 확인 가능.
  - 해금(unlocked): 상점 등장 풀에 추가됨 (등록과 동시에 해금).
